# 画面（apps/web）

ゲームの画面（3D の店）を主にし、会話の窓・旅程・地図・出典のパネルを重ねる画面と、旅のしおりです。Vite + React + Tailwind CSS で作り、状態は Zustand のストアだけが持ちます。

```text
src/state/      ストア。SSE のイベントをストアの更新に変える（events.ts）
src/transport/  接客サーバーとの通信（POST で送りながら SSE で受け取る）
src/testing/    テストだけで使う通信の口の代わり（記録した相談を再生する。ビルドには入らない）
src/ui/         HUD・会話の窓・パネルの部品と、画面の中のしおり
src/account/    ログインと自分の旅（Firebase は、ログインを用意しているときだけ読み込む）
src/i18n/       日本語と英語の辞書
src/scenes/     3D の店（店内・スタッフ・外観と入店のカメラ）
e2e/            Playwright の通しテスト
```

## 動かす

```bash
pnpm dev
```

画面（:5173）と接客サーバー（:8787）が一緒に立ち上がります。画面はいつも接客サーバーと話し、Vite が `/api` と `/shiori` を接客サーバーへ中継します（中継先は `MATSURI_SERVER_ORIGIN` で変えられます）。

接客サーバーは、既定で**モックモード**（`MATSURI_AGENT_MODE=mock`）です。AI の返答だけが `data/samples/conversations/` の記録した相談の再生になり、画面・通信・旅程・しおりは本物のまま動きます。何を送っても、記録の次の発言への返答が流れます。

| URL の引数     | 意味                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| `?sample=<id>` | 接客サーバーが再生する記録（`data/samples/conversations` の名前）。モックモードだけ |

記録の再生の速さは、接客サーバーの `MATSURI_REPLAY_SPEED` で変えます。

### 接客サーバーとのつなぎ

- `?sample=<id>` は、`POST /api/session` の本文 `{ "sample": "<id>" }` で接客サーバーに渡します
- 合言葉（`ACCESS_PASSCODE`）を設定したサーバーでは、`/api` のすべての呼び出しに `x-access-passcode` ヘッダーを付けます。断られたら入口（相談の途中なら小さな窓）で聞き直します。合言葉はメモリにだけ持ち、URL にも保存にも入れません
- SSE を始める前に断られたら、サーバーが本文で送る一文（`code`・`message`・`retryable`）を会話欄に出します。「相談が見つからない」（404）のときは、新しい相談を自動で始めます
- しおりを開けるようになったら、共有の URL（ログインしていなければ `/shiori/<旅程の ID>`、自分の旅程なら共有の ID の `/shiori/sh-…`。用意できなければ、その旨と「もう一度試す」を出す）を出します。画面の中のしおり（`src/ui/ShioriPage.tsx`）は1枚の紙面でブラウザの印刷を使い、共有の URL では接客サーバーが作る A4 のしおり（HTML と PDF）が開きます

## 確かめる

```bash
pnpm test                                        # ストアとイベントの変換（Vitest）
pnpm --filter @matsuri-ikoka/web exec playwright install chromium
pnpm --filter @matsuri-ikoka/web test:e2e        # 画面の通しテスト（Playwright。接客サーバーをモックモードで立ち上げる）
```

- 手元の Chrome で走らせるときは `PLAYWRIGHT_CHANNEL=chrome` を付けます
- 通しテストは、地図のタイルを取りに行きません。取りに行くときは `E2E_ALLOW_TILES=1` を付けます
- 見直し用のスクリーンショットは `test-results/screens/` に保存します（Git の対象外）

## 状態の決まり

- 正しい状態はストアだけが持ちます。SSE のイベントは `src/state/events.ts` の純粋な関数でストアの更新に変え、部品はイベントを直接受けません
- 届いたイベントは `src/state/store.ts` の1か所でスキーマで検証し、形が違えば捨てて会話欄に知らせます
- `done` の前に接続が閉じたら、会話欄に「もう一度送る」を出します。自動では再接続しません
- データとモデルの文章は文字列として表示し、HTML として埋め込みません（地図のピンも `textContent` で入れます）

## ゲームの画面

画面はいつも 3D の店が主役で、その上に HUD（`src/ui/Hud.tsx`）を重ねます。並びは [画面の仕様](../../docs/spec/screens.md#店の画面の並び) のとおりです。

表示は「探索」「会話」「計画」の3つの場面に分け、そのとき要るものだけを重ねます。

- 探索：左上にロゴと日付の小さな札（旅の日と出発の駅）、右上に丸いボタン（お知らせ＝会話の記録・旅のこだわり・設定・使い方・ログインと自分の旅）、右下に小さな操作の案内（X 旅程詳細・Y 地図・M メニュー。キーボードの X・Y・M、ゲームパッドの X・Y・スタートでも同じ）、下に小さな「話しかける」のボタン（`GreetingBar`）。会話の窓は出さず、コンシェルジュの頭の上に「！ 相談はこちら」の目印を出す
- はじめての操作の案内（`src/ui/Play.tsx` の `Tutorial`）は、最初に店に入ったときだけ出す。閉じるか話しかけると消え、この端末で覚えておく（`src/ui/storage.ts`）。そのあとは「使い方」から、操作の一覧と店の中のようす（近くにあるもの・見つけた隠れひよこ・店の時計の時刻）を開ける。店の中のようすは、いつも読み上げにも伝える
- 会話：会話の窓（`src/ui/Dialogue.tsx`）を画面の下に出す。和紙の色の枠に、大きな顔の絵と名札、いまの一言（1〜2文に縮め、「つづきを読む」で全文）。その下に、選んで進める相談（`src/ui/Consult.tsx`）か返事の選択肢、いちばん下に自分の言葉で書く小さな欄（書いている間だけ広がる）。返答を待つ間は、短いひとことと考える仕草を出す。話しかける（E・タップ・ボタン）と出て、× でしまえる。返答やエラーが届いたときも出る
- 計画：旅のしおり（`src/ui/ItineraryPanel.tsx`。旅程・地図・出典）を右から開く。上に旅の進み具合（祭りの候補 › 旅程の案内 › 確認 › 旅のしおり）を出す。祭りの候補は絵葉書のカード（`src/ui/CandidateCards.tsx`）で重ね、エリア・時期・テーマで絞り込める
- 相談の入口：最初に「祭りから探す」「旅行計画から探す」の2択を出す。選ばずに文字で書いて送ると、今までの相談として受ける
- 祭りから探す相談：種類 › 季節 › 地域 › その他の希望 を選び、結果を候補カードと同じ部品で見比べて1つ決める（`src/state/festivalSearch.ts`、`POST /api/festivals/search`）。決めたら「旅行計画を作成する」「ここで終わる」「ほかの祭りを見る」を選ぶ
- 選んで進める相談（旅行計画）：誰と › いつ › どこへ › 日帰り・泊まり › 楽しみ › 食べたいもの › 旅のスタイル › 確認 の段階で選ぶ。どの項目にも「おまかせ」と「その他」（自由記述）がある。確認で、選んだ内容を1つの発言にまとめて送る（`src/state/consult.ts`。今週末・来月などは、ここで具体的な日付にする）
- 見た目は `src/index.css` のトークン（`washi`・`line`・`radius-panel`・`radius-card`・`shadow-soft`・`shadow-lift`）でそろえる。重い影より、薄い輪郭線と柔らかい影を使う
- 待ち時間の豆知識係（`src/ui/Waiting.tsx`）：返答を待つ間、コンシェルジュが祭りのデータの小話・見どころ・作法を出典つきで話す。候補が出る前は全体から、候補が出たあとは候補と主役の祭りから選ぶ。7秒ごとに次へ移り、「次の話」「止める」ができる。だれが何をしているかと経過時間も出す
- 店内のようす（左上）：いま動いているスタッフを文字で出す。3D の動きと吹き出しと同じ情報
- クイズ・しおりの完成の演出
- 狭い画面では、操作の案内をメニューにまとめ、会話の窓を主にする

3D のカメラは、`cam.main` と `cam.shiori` の間の高さから、設計した 16:9 の枠で画面を覆うように映し、旅人に合わせて横と奥行きになめらかに動きます（向きは変えず、画面比には画角と `setViewOffset` で合わせる）。3D を描けないときの知らせは、重なる部品の幅（`ShopSceneProps.frame`）を避けた場所に置きます。

## 3D の店

- `src/scenes/ShopScene.tsx` は `ShopSceneProps`（`src/state/scene.ts`）を受け取り、ストアの状態だけを読む。SSE のイベントは受けない
- 誰がどこで何をするか（立つ場所・モーション・表情・小物）は、`src/scenes/choreography.ts` の純粋な関数で決める
- GLB は `assets/3d/models` だけに置き、Vite の `?url` で配る（ビルドでは `dist/assets` に出す）。meshopt と WebP をそのまま読む
- 入店のカメラは、ページを開いて1回だけ流す。店の外観の画面には、通りから見上げた外観を背景に出す
- 旅人のペンギン（`src/scenes/Player.tsx`）は、WASD・矢印・ゲームパッドの左スティックと十字キー・タップで動かす。歩けるのは `nav.customer` を 3 cm の升目にし、体の太さ（12 cm）ぶん縁から削ったところだけ（`src/scenes/navmesh.ts`）で、柵や家具に体が重ならず、壁に沿って滑り、縁の段は回り込む。1回の移動は 3 cm ずつ刻んで確かめる。タップした場所へは、床を 10 cm の升目にした A* で家具をよけて歩く
- 近くで使えるもの（`src/scenes/controls.ts`）：スタッフ（話す。窓口はコンシェルジュ）、仕掛け12個、ソファとベンチ（座る。立つと座る前の床へ戻る。柵の向こうの従業員の椅子は知らせるだけ）、隠れひよこ、のれん（外に出る）。旅人の頭の横に「E ○○」を出し、E・Enter・Space（ボタンなどに焦点がないとき）・ゲームパッドの A で使う。近くに何もなければ会話の窓の入力欄へ。入力欄では Esc で旅人の操作に戻る
- 遊びの状態（近くにあるもの・座っているか・ひよこ・仕掛けの結果）は `src/state/play.ts` のストアに持つ。相談の状態とは分ける
- 入口から 2 m 以内では入口の壁を透かす。時計は本物の時刻を指す
- カメラは旅人に合わせて動き、利用者が回せる：マウスのドラッグ・ホイール、2本指（つまむ・動かす）、キーボードの Q・R（回す）・Z・C（寄る・引く）・V（戻す）、ゲームパッドの右スティックと LB・RB。回せるのは店の開いた側から見える範囲だけで、壁より低いところでは店の箱の内側に収め、床に潜らない（`clampOrbit`・`keepCameraInside`）
- のれんの前で通りへ向かって進む（または「外に出る」を使う）と、店の外観に戻る。相談はそのまま残り、また入ると入店のカメラから始まる
- 3D は遅れて読み込み、描けるまでは店の外観と「店に入っています」を出したまま待つ（2D の見取り図は出さない）。外観の画面にいる間に、店内で使うモデルを先に読み込む。外観の画面はモデルの複製を使い、店内と同じ物体を取り合わない。入店のカメラが終わるまでは、案内・吹き出し・「話しかける」を出さず、旅人も動かさない。2D の見取り図には切り替えない。動きを減らす設定（`prefers-reduced-motion`）でも 3D を出し、動きを控えめにする。WebGL が使えない・読み込めないときは「3D を描けない」知らせを出す
