# ADR 0012：頼まれた旅の見回りは、コードが先に比べ、変化があるときだけ Managed Agents に読ませる

- 状態：採用
- [ADR 0009](0009-weekly-research-on-managed-agents.md) の定義の置き方を引き継ぐ。Webhook を置かないという判断は、見回りについては変える

## 背景

しおりを受け取ったあとに祭りの中止・順延・時間の変更や宿の空きの変化があっても、自分で見に行かないと気づけない。週次の調査は祭りのデータの更新のためのもので、確定した開催回は調べない。旅の前の変化を知らせるには、頼まれた旅について、もっと短い間隔で確かめる必要がある。

一方で、見回りには次の難しさがある。

- ページはほとんどの回で変わらない。毎回モデルに読ませると費用がかさむ
- 祭りの公式サイトは前もって列挙できないので、Web の許可リストを前提にできない。ページの文章に悪い指示が書かれているかもしれない
- 通知は人の確認を通らずに利用者へ届く。週次の調査のように、人がマージする最後の関門がない
- 起動の再送や、インスタンスの停止で、同じ作業が二重に走ったり途中で止まったりする
- 公開のサーバーがセッションを作るので、長く使える鍵を公開のサーバーに置くことになる

## 判断

- **コードが先に比べる**。サーバーが公開のページを取得し、行に分けて前回と比べる。変わらなければ調べた時刻だけを残し、モデルを呼ばない。変わったページとコードで読めないページだけを見回り係に渡す
- **見回り係は Managed Agents のセッションにする**。ページの取得の道具だけを持ち、秘密の値・データベースの権限・利用者の情報を持たない。渡すのは祭りの公開の情報と URL と変わった行だけで、型が決まった項目のほかを受け付けない。ページの取得の道具は発言にある URL しか開けないので、対象の URL は開始の発言に入れる
- **起点は内部の API にする**。対象は頼まれた旅から実行のたびに決まるので、定期実行（Deployment）の決まった発言では渡せない。Cloud Scheduler が OIDC のトークンつきで呼ぶ。セッションの予算と1回の対象の数の上限を付ける
- **結果は Webhook で受け取り、定期の起動でも確かめる**。Webhook は署名を確かめ、配信の ID で重複を除き、薄い通知を受けてから結果を取りに行く。Webhook は失われることがあるので、次の起動で古い実行を確かめ直す。受け取ったら、または時間切れにしたら、セッションを止めて消す。セッションにはページの文章が残るため
- **報告はファイルでなく最後の返答で受け取る**。見回り係に書き込みの道具を持たせないため
- **検問はコードで行う**。変化の種類はコードが前回の値と比べて決める。変わったと言う値が、コードで読み直した新しい行に書いてあるときだけ認める。確かさは主張ごとに決め、確かめられないときは値を持たないお知らせに落とす。比べる元を進めるのは、見回り係が実際に開いたと確かめられたページだけにする
- **祭りごとの作業に実行権を持たせる**。Firestore のトランザクションで取り、作業中は延ばす。切れた実行権は別の実行が引き継ぐ
- **宿の空きはモデルを使わない**。今の空室検索の処理をコードで呼ぶ。人数や日付は旅ごとに違うので、祭りごとにはまとめない
- **定義と鍵を週次の調査と分ける**。下の「置き場と鍵」のとおり

### 置き場と鍵

見回りの定義は `managed-agents-patrol/` に置き、週次の調査と別のワークスペース（`matsuri-patrol`）と別の `claude-lock.json` で管理する。

- 公開のサーバーは、セッションを作るために長く使える API キーを持つ。[ADR 0004](0004-authentication.md) のとおり、公開の URL は API キーで動かす
- [ADR 0009](0009-weekly-research-on-managed-agents.md) は、週次の調査のワークスペースに長く使える鍵を置かないと決めている。見回りを同じワークスペースに置くと、公開のサーバーの鍵が週次の調査に届き、この判断に反する
- `ant apply` はディレクトリを深さに関わらず歩き、1つの lock は1つのワークスペースにしか対応しない。`managed-agents/` の中に置くと、`update-festivals.yml` の適用で週次の調査のワークスペースに入る。そのため別のトップレベルのディレクトリにする
- 鍵が届くのは見回りのワークスペースのエージェント・環境・セッション・ファイルだけで、週次の調査の調査リスト・定期実行・報告のファイルには届かない。鍵が漏れても、できるのは見回りの範囲で、利用額の上限もワークスペースごとに持てる
- 接客の `ANTHROPIC_API_KEY` とも分け、見回りだけを止めたり鍵を回したりできるようにする
- 定義の適用は当面、人が見回りのワークスペースの資格情報で行う。週次の調査の Workload Identity Federation のルールは広げない

### ページの中の指示への備え

指示の見分けは文字の形によるもので、言い換えをすべて見分けることはできない。見回り係がページの言葉に引きずられることも防ぎ切れない。そこで、指示を見分けられなくても被害が小さくなる形にする。

- 見回り係に、利用者の情報も権限も渡さない
- 指示に見える行は、見回り係に渡さず、根拠にも使わない
- 開催の変更と中止は、値がコードで読んだ新しい行に書いてあり、公式か2つのサイトでそろうときだけ認める。別の年の行や、別の催し・一部の催しの行は根拠にしない
- 通知は決まった形の値と出典だけを持ち、ページの文章を入れない

悪いページが主催者の発表のように書かれていれば、そのサイトが公式か2つそろう場合に限り、通知になり得る。通知には出典を付け、組み直しは利用者が承認するまで行わない。

### ほかの案

| 案                                                   | 採らなかった理由                                                                                              |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 毎回、見回り係に読ませる                             | ほとんどの回でページは変わらないので、費用の大半が無駄になる                                                  |
| 週次の調査の頻度を上げる                             | 調査の深さが要らない。結果は PR を通るので、変化が届くまで時間がかかる                                        |
| 定期実行（Deployment）と Memory Store で渡す         | 対象を Store に置く手順が増える。旅の変化を待たずに同じ費用がかかる                                           |
| 終わりをポーリングで待つ                             | Cloud Run の CPU はリクエストの間だけ割り当てられるので、長く待てない。起動の間隔でしか結果を受け取れなくなる |
| ページを見回り係に読ませず、コードだけで判定する     | 中止や順延の文は書き方が多様で、コードだけでは見落とす。スクリプトで描くページも読めない                      |
| 見回り係の報告をそのまま通知にする                   | ページの指示で報告を変えられると、人の確認なしに利用者へ届く                                                  |
| 実行権を持たず、起動の間隔だけで重ならないようにする | 起動の再送やインスタンスの停止で、セッションと費用が二重に発生する                                            |
| 週次の調査と同じワークスペースに置く                 | 公開のサーバーの鍵が週次の調査に届く。ADR 0009 の判断に反する                                                 |

## 結果

- 良い点：変わらないページに費用がかからない。見回り係が乗っ取られても、利用者の情報にも権限にも届かない。起動が2回届いても二重に走らず、止まった作業は引き継がれる。公開のサーバーの鍵が漏れても、週次の調査には届かない
- 引き受けること：
  - はじめて読んだページは比べる元を残すだけなので、見回りを頼む前の変化には気づかない。旅程を確定する前の再確認で補う
  - コードで読めないページの変更は、値を持たないお知らせになる。利用者が出典のページを開いて確かめる
  - 比べる元はハッシュだけなので、なくなった行の文章は分からない。見回り係にはページを開いてもらう
  - `robots.txt` で断られたページは見回らない
  - 天気の変化はまだ見回らない
  - 宿の空きは検索の上位の結果で見るので、結果が上限まであるときは候補の空きが分からず、その回は知らせない
  - Webhook の受け口が公開の URL に増える。署名を確かめる前に処理を始めないことで補う
  - 見回りのワークスペースの定義の適用は、人が行う
