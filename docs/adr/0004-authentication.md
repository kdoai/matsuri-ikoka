# ADR 0004：場面ごとに Claude への認証を分ける

- 状態：採用

## 背景

接客エージェントとデータの更新は Claude を呼ぶので、認証の情報が要る。動かす場面は、モック、手元での開発、公開している URL、データの更新と分かれていて、だれが使うかも違う。リポジトリは公開しているので、秘密の情報を一切置けない。

## 判断

| 場面                 | 認証                                                                                 | 秘密の置き場所                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| モックモード・CI     | 不要                                                                                 | —                                                                                                                      |
| 手元での開発（live） | 各自の API キー。開発者自身の手元では、ログイン済みの Claude Code の資格情報も使える | `.env`（Git の対象外）                                                                                                 |
| 公開している URL     | API キー                                                                             | クラウドの秘密情報の管理（Secret Manager）。CI からのデプロイは Workload Identity 連携で認証し、鍵のファイルを作らない |
| データの更新         | API キー                                                                             | GitHub Actions の Secrets                                                                                              |

- Claude のサブスクリプションのログインは、開発者自身の手元の開発にだけ使う。ほかの人が使うもの（公開している URL、データの更新）は、すべて API キーで動かす
- API キーはブラウザに渡さない
- 公開している URL の入口には、合言葉と1日の相談回数の上限を置き、使いすぎを防ぐ

## 結果

- 良い点：リポジトリに秘密の情報を置かずに済む。キーを持たない人も、モックモードで相談からしおりまでを確かめられる
- 引き受けること：
  - `.env` を Git の対象外にし、`.env.example` には変数名と説明だけを書く
  - CI で gitleaks を走らせ、秘密の情報の混入を止める
  - 費用の上限は、Anthropic のコンソールでも決めておく
