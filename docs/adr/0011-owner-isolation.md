# ADR 0011：相談と旅を利用者ごとに分け、経路ごとの決まりで既定で断る

- 状態：一部置き換え（[ADR 0015](0015-keep-trips.md)。前に渡したしおりの URL は、持ち主が付く前の版のまま期限まで開ける）

## 背景

旅の相談には、日程・出発地・同行者の情報が入る。これから旅の途中まで付き添うようになると、現在地や困りごとも扱う。複数の人が同時に使っても、他の人の相談・旅程・通知に触れてはいけない。

いまの作りには、次の隙間があった。

- Firestore のセキュリティルールは全拒否だが、サーバーの Admin SDK には効かない。行単位の制限に当たるものは、サーバーのコードだけが担っている
- 相談の API は相談の ID だけで動き、ログインして使っても利用者に結びつかない
- 持ち主のある旅程でも、旅程の ID を知っていれば `GET /api/itinerary/:id` と `GET /shiori/:id` で読める
- 回数と同時に返事を作る数の上限は、全体と IP の単位で、1人が枠を使い切れる

## 判断

- **持ち主で絞った保存の口**：利用者の旅の読み書きは `storage.forOwner(持ち主)` が返す口にしか置かない。持ち主の ID は `OwnerId` という型にし、ID トークンを確かめた値と、保存した相談の持ち主からしか作らない。絞らない呼び出しは型の検査で落ちる
- **既定で断る経路**：経路は `SecureRoutes` からしか足せず、足すときに「だれでも・相談の持ち主・ログインした持ち主・内部」のどれかを宣言する。決まりに応じて、ハンドラが受け取るものを変える（相談を開く口、その人に絞った保存の口など）。宣言のない経路があるとサーバーは起動しない
- **相談の持ち主**：ログインして使った相談は、はじめて使った利用者に結びつけ、ほかの人とログインなしの人には 404 にする。ログインなしの相談は、推測できない ID のまま、いまの使い方を保つ
- **旅程の持ち主**：ログインした相談で組んだ旅程は、残す前からその人だけのものにする（`consultOwnerUid`）。「残す」（`ownerUid`）の意味は変えず、一覧に出して消さないのは残した旅だけにする。持ち主のある旅程は、持ち主か、明示して作った共有の ID からだけ読める
- **あるかどうかを見せない**：ほかの人のものは、ないときと同じ応答の 404 で断る。いままで 403 を返していた「ほかの人が残した旅を残す」も 404 にする
- **利用者ごとの上限**：1日の回数と同時に返事を作る数を、利用者ごと（ログインしていなければ IP ごと）に持つ。新しい必須の環境変数は作らず、回数は `DAILY_CHAT_LIMIT_PER_IP` を使い、同時の数の既定は全体の半分を切り上げた数にする
- **内部の入口**：定期実行と Webhook のために、合言葉やログインとは別の検証（OIDC・署名）を挟む口を作る。設定がなければ、その入口だけが断る
- **新しいデータの置き場**：旅と利用者に結びつく新しい種類のデータは、持ち主を含むパス（`users/{uid}/trips/{id}/…`）に置く。いまの `itineraries`・`shares`・`sessions` は移さない
- **ログ**：例外の文には入力が入ることがあるので、種類と場所だけを残す

## 検討した案

- **Firestore のルールで行単位に守る**：Admin SDK には効かない。ブラウザから直接読み書きする形に変えると、検証や TTL をサーバーで守れなくなるので、とらない
- **利用者の ID を各メソッドの引数で渡す（いままでの形）**：渡し忘れや、確かめていない値を渡す誤りを型で止められない
- **経路の表を別に持ち、ミドルウェアで照らす**：宣言と実装が離れ、決まりとハンドラが受け取るものが結びつかない
- **相談の旅程は「残す」まで持ち主なしにする**：しおりの埋め込みは変えずに済むが、ログインした人の共有していない旅程を、ID を知る人が読める形が残る
- **ログインした相談の旅程をすべて残した旅にする**：残すと押していないのに一覧に出て、消えずに残り続ける

## 結果

- 良い点：保存の口と経路の型で、ほかの人のデータに触れるコードが書きにくくなる。新しい経路は決まりの宣言と、利用者ごとの表への追加がないとテストが落ちる。後続のガイドの機能は、この口の上に作れる
- 引き受けること：
  - 持ち主のある旅程は旅程の ID では開けない。残した旅の、前に渡した `/shiori/{旅程の ID}` の URL は開けなくなる。共有の ID の URL はそのまま開ける
  - ログインしている人の店内のしおりは、共有を作って開く。同じ内容で期限に余裕のある共有は使い回し、内容が変われば別の共有になる。作った共有は30日で消える
  - ログアウトすると、ログインして使った相談は続けられない（画面は新しい相談を始める）
  - 同じ IP から同時に使う人が多いと、ログインしていない間は、全体に空きがあっても 503 になることがある（retryable）。ログインすれば利用者ごとに数える
  - 1日の回数と同時の数の上限は、ADR 0005 のとおりインスタンスごとに数える
  - メールアドレスの確かめなしで登録できるので、1日の回数は、ログインしていても IP でも数える。同じ IP の人は、ログインしていても枠を分け合う
  - 持ち主の ID を作る口の例外は、人が権限を持って手元で実行する `apps/server/scripts/trial-account.ts` だけで、サーバーの経路からは届かない
  - 別のインスタンスが、相談に持ち主が付く前の状態をメモリに持ち続けることがある。インスタンスは最大1つなので、切り替えの短い間にしか起きない。インスタンスの最大数を増やすときは、メモリの相談の持ち主を保存の口と照らす処理を足す
  - 例外の文をログに残さないので、失敗の調査は種類とスタックの場所から始める
