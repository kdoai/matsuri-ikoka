# ADR 0001：接客エージェントに Claude Agent SDK（TypeScript）を使う

- 状態：採用

## 背景

接客は、利用者と話すコンシェルジュ1人と、裏で調べものをするスタッフ3人（祭り調査係・周辺係・旅程係）で受け持つ。必要なものは次のとおり。

- 役割ごとに指示と使えるツールを分けたエージェント
- 日程のルールや営業時間の検証を、モデルではなくコードで実行するツール
- ツールを呼ぶ前後に画面へイベントを送る仕組み。待っている間に、だれが何を調べているかを見せる
- 画面とサーバーで、同じ型の定義を使えること

## 判断

Claude Agent SDK の TypeScript 版で接客エージェントを組む。

- スタッフはサブエージェントにし、それぞれに担当のツールだけを渡す
- 6つのツールはプロセス内の MCP サーバーとして定義し、入出力を Zod で検証する。計算は Agent SDK に依存しない `domain/` の関数で行う
- ツールの前後のフックから SSE イベントを出す。吹き出しの文章はツールの入力から決まった型で作り、モデルには書かせない
- 画面（React）と同じ TypeScript で書き、`packages/schema` を共有する

### ほかの案

| 案                                          | 採らなかった理由                                                     |
| ------------------------------------------- | -------------------------------------------------------------------- |
| Messages API とツールの呼び出しを自前で回す | サブエージェント、フック、ツールの許可の仕組みを自分で作ることになる |
| Agent SDK の Python 版                      | 画面と言語が分かれ、スキーマを2重に持つことになる                    |

## 結果

- 良い点：エージェントの構成・ツール・フックを、SDK の仕組みのまま書ける。スキーマを1か所で持てる
- 引き受けること：
  - SDK は何も指定しないと開発環境の設定やスキルを読み込むため、接客エージェントでは明示的に切り離す（[アーキテクチャ](../architecture.md#接客エージェントを開発環境から切り離す)）
  - SDK の版は lockfile で固定し、上げるときは動作を確かめてからにする
  - キーがなくても画面を作れるよう、記録した相談を再生する mock の口を用意する
