# ADR 0013：旅のガイドの会話は組み込みの道具なしで動かし、変更は直しの提案にする

- 状態：一部置き換え（緊急の案内は [ADR 0014](0014-guide-no-emergency-contacts.md)）

## 背景

しおりのあとも、旅のことをいつでもガイドに相談できるようにする。ガイドはその人の旅程と手帳を読むので、ページや発言の中の指示で動かされると、利用者の情報に届いてしまう。旅の途中では、体調や事故の相談も来る。

## 判断

- **組み込みの道具を持たせない**：ガイドは `tools: []` で動かし、許すのは決まったツールの名前だけにする（ワイルドカードを使わない）。Web を読む役は、ツールの中の1回きりの調べ役に分ける。調べ役には質問だけを渡し、ガイドには調べ役が自分の言葉で書いた短い答えと読んだページの URL だけを返す
- **旅と利用者はサーバーの文脈から決める**：ツールの入力に旅の ID や利用者の ID の項目を置かず、余分な項目があれば断る。プロンプトにも旅の ID を入れない。モデルが書けないので、他の人の旅についての呼び出しを作れない
- **変更は影響する予定だけの直しの提案にする**：ガイドに旅程の全体を書かせず、予定の ID を指した直し（時刻を変える・外す・置き換える・足す）を書かせ、コードが今の旅程に当てて、`update_itinerary` と同じ検証に通す。変えない予定を書き写さないので、壊れない。提案は承認されるまで旅の版に入らない
- **手帳に残すものをコードで照らす**：残す文が、この発言で利用者が話したことかを、発言の本文と照らして決める。発言の本文はサーバーが持ち、モデルの入力からは受け取らない。現在地・体調の詳しい内容・連絡先・秘密の値は言葉で見分けて断る。見分けられないものは残さないほうへ倒す
- **旅の下に置くのは残した旅のデータだけ**：残す前の旅とログインしていない相談では、手帳や提案を相談の中にだけ持つ。残されていない旅程は30日で消えるので、旅の下に置くと、旅程が消えたあとも手帳が残ってしまう。残したときに旅の下へ移す
- **緊急の案内はコードが出し、断らない**（[ADR 0014](0014-guide-no-emergency-contacts.md) で置き換え）：発言の言葉で見分け、モデルも保存の口も待たずに公的な連絡先を送る。上限・混雑・モデルの失敗でも、連絡先と決まった文を返し、いつもの案内（新しく始める、もう一度送るなど）も添える。緊急でない発言に当たっても案内は失わず、ガイドが答えられるときはそのまま答える。ふつうの相談に当たると決まった文やモックの緊急の案内が混ざるので、紛らわしい言葉は形で見る
- **費用と回数の上限は、ログインしている人の分を保存の口に残す**：メモリだけだと、インスタンスが止まるたびに数え直されて、1日の上限にならない。費用には、ツールの中の調べの分も含める
- **設定がなければ、ガイドの入口だけが断る**（のちに、`MODEL_GUIDE` がなければ店のコンシェルジュのモデルで動かすように改めた。ガイドは店のコンシェルジュと同じ人で、設定の漏れでガイドと話せなくなるのを避けるため）：`MODEL_GUIDE` を起動に必須の設定にしない。設定がなければサーバーは起動し、今の相談は動き、ガイドの入口だけが 404 で断る

## 検討した案

- **会話全体を Managed Agents で動かす**：今の SSE とフックをそのまま使えない。会話は Agent SDK で動かし、見回りだけを Managed Agents にする
- **ガイドに Web の道具を渡す**：ページの指示に乗っ取られたとき、利用者の情報を持った役が外へ読みに行けてしまう。とらない
- **旅程の全体を書かせて提案にする**：何日もの旅では長く、変えない予定を書き間違えやすい。ツールの結果も大きくなる。とらない
- **手帳に残すかをモデルだけに任せる**：ページの指示に従ってしまったときに止められない。コードで照らす
- **発言の言葉で見分けたら、モデルを呼ばずに決まった文だけを返す**：緊急でない発言（「熱中症の対策は？」など）に答えられなくなる。連絡先を先に出して、モデルにも答えさせる
