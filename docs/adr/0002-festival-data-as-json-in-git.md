# ADR 0002：祭りのデータを1件1ファイルの JSON にし、Git で管理する

- 状態：採用

## 背景

祭りの情報は、年ごとに変わる部分（開催日・時間・雨天の扱い）と、ほぼ変わらない部分（由来・見どころ・作法）がある。情報には必ず出典が要り、誤りは祭りを運営する方や利用者から訂正されることがある。扱う祭りの数は数百から数千の見込みで、書き込むのは収集と更新の仕組みと人だけ。

必要なものは次のとおり。

- いつ、何が、なぜ変わったかを追える履歴
- 取り込む前の検証（出典のない情報や、形の崩れたデータを入れない）
- 自動の更新と人の確認を、同じ流れで扱えること

## 判断

- 1つの祭りを1つの JSON ファイル（`data/festivals/{id}.json`）にし、Git で管理する
- 形は `packages/schema` の `FestivalSchema` で定義し、CI ですべてのファイルを検証する
- サーバーはデータをコンテナに同梱し、起動時にメモリへ読み込む
- 更新は、人の手でも自動の収集でも、PR で届ける。内容の変わらない安全な変更（確認日の更新など）だけを自動でマージし、開催日の変更や中止などは人が確かめる

### ほかの案

| 案                                         | 採らなかった理由                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------ |
| データベース（Firestore、PostgreSQL など） | 運用の手間が増え、変更の履歴とレビューが見えにくい。読み込みだけの用途には大きすぎる |
| 1つの大きな JSON ファイル                  | 差分が読みにくく、複数の更新がぶつかりやすい                                         |

## 結果

- 良い点：差分がそのまま更新の履歴になり、PR でレビューできる。CI の検証を通らないデータは入らない。訂正の依頼を Issue から PR へつなげられる
- 引き受けること：
  - データを変えるたびにデプロイが要る
  - 祭りの数が大きく増えたら、読み込みと索引の作り方を見直す
