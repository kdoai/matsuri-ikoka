# ADR 0003：3D の店内を、状態の見た目の層にとどめる

- 状態：採用

## 背景

画面では、やわらかいローポリの 3D の店内でスタッフが働く様子を見せる。スタッフが持ち場へ歩き、調べている間は吹き出しが出るので、待ち時間に何が起きているかが分かる。

一方で 3D は、端末によっては重く、読み込みに失敗することもある。動きの多い画面が苦手な人もいる。3D がなければ情報が伝わらない作りにすると、こうした人が使えなくなる。

## 判断

- 正しい状態はストア（Zustand）だけが持つ
- SSE のイベントをストアの更新に変える処理は1か所（`apps/web/src/state/`）にまとめ、部品はイベントを直接受けない
- 3D の店内と、文字で読む部品（会話の窓・パネル・スタッフの一覧）は、どちらも同じストアを読むだけにする
- 3D に出す情報（スタッフが何をしているか、吹き出しの文章、相談の進み具合）は、すべて文字でも読めるようにする
- 画面は 3D だけにし、2D の店や通りには切り替えない。動きを減らす設定（`prefers-reduced-motion`）のときは、3D のまま動きを控えめにする。WebGL が使えないときは、その知らせを出し、相談は文字の部品で続けられる

## 結果

- 良い点：3D がなくても、相談からしおりまでの情報がすべて伝わる。3D は、ストアの形さえ決まっていれば、ほかの画面と切り離して作れる
- 引き受けること：WebGL が使えない端末では店や通りの絵を出せない（相談・知らせ・しおりは文字の部品で使える）
