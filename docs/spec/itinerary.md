# 旅程の仕様

旅程は「旅全体の情報」と「日ごとの、時刻順の予定の並び」でできています。予定の1つ1つが、なぜそこに入っているかの理由と出典を持ちます。形は `ItinerarySchema` です。

週末のお出かけ（祭りだけを見に行く1件の旅程でもよい）から、6泊7日の旅までを同じ形で扱います。日数は泊数＋1です。

## 旅全体の情報

| 項目                 | 意味                                                                                                                                                          | 例                                          |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `id`                 | 旅程の ID。サーバーが付ける                                                                                                                                   | trip-…                                      |
| `title`              | しおりの表紙に出す名前（40字以内）                                                                                                                            | 鈴鳴の灯籠と川べりさんぽ                    |
| `origin`・`returnTo` | 出発地と帰着地（駅名まで）                                                                                                                                    | みなと中央駅                                |
| `party`              | 大人と子どもの人数（シニア・幼児の内訳つき。下を参照）                                                                                                        | 大人2                                       |
| `preferences`        | こだわり4項目（下の表）                                                                                                                                       | 大人だけ・穴場・地元の店も楽しむ・電車      |
| `budget`             | 旅の予算（任意）。聞き取った条件をサーバーが付け、旅程係には書かせない。画面としおりでは、言われた数え方（1人あたり・全員で）と、人数で換算したもう一方を出す | 全員で 50,000円まで（1人あたり 25,000円）   |
| `mainFestivalId`     | 主役の祭り                                                                                                                                                    | suzunari-toro                               |
| `verification`       | 開催の確かめの結果（決定のときに、候補の確かめの結果を書く）                                                                                                  | 確認前 / 予定どおり（出典つき）             |
| `notes`              | 持ち物と注意。子連れ・季節・祭りの性格から出す                                                                                                                | 懐中電灯                                    |
| `alternatives`       | 主役の祭りに行けないときの代わり（雨の日、中止のとき）                                                                                                        | 屋内中心の過ごし方                          |
| `version`            | 修正のたびに増える版                                                                                                                                          | 2                                           |
| `days`               | 日ごとの旅程（1〜7日。下の表）                                                                                                                                | 8/15・8/16 の2日                            |
| `considered`         | 周辺係・宿の係が見つけた場所の採否と理由（任意。下を参照）                                                                                                    | 鈴鳴和紙の館：採った                        |
| `gaps`               | 点検で見つかった不足（任意）。サーバーがコードで決める。分からないところは推測で埋めず、ここに書く                                                            | 昼の食事の案がない                          |
| `evaluation`         | 評価係の採点（任意。[旅程の評価](#旅程の評価) を参照）。サーバーが付ける                                                                                      | 網羅 85・具体さ 80・無理のなさ 100・出典 90 |

旅程で使った出典の一覧は、予定・日ごとの天気・再確認・宿の候補・食事の案・帰りの最終の出典から重複を除いて集めます（`collectItinerarySources`）。

### 人数の内訳

`party` の `adults` は中学生以上の全員、`children` は小学生以下の全員です。内訳の `seniors`（大人のうちのシニア、65歳以上）と `infants`（子どものうちの未就学の子ども）は任意で、ないときは 0 として扱います。内訳は大人・子どもの内数なので、`seniors` は `adults` 以下、`infants` は `children` 以下です。

## 日ごとの情報

| 項目         | 意味                                                                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `date`       | その日の日付。日は1日ずつ続けて並べる                                                                                                         |
| `weather`    | その日の予報、または「予報前」「取得できなかった」。サーバーが日ごとに付ける                                                                  |
| `items`      | その日の時刻順の予定（1件以上）                                                                                                               |
| `stay`       | その夜に泊まる地域（`area` と補足の `note`）と、調べた宿の候補（`lodging`、任意）。`null` はその日に帰る。最後の日は必ず `null`               |
| `meals`      | 滞在の時間帯にかかる食事（昼・夜）ごとの案（任意。下を参照）                                                                                  |
| `lastReturn` | 帰りの最終の目安（任意）。乗る駅（`station`）と、最終の時刻（`departBy`）。時刻を書くときは出典が要る。分からなければ `null` にして不足に書く |

- 接客が書くのは泊まる地域と注意だけです（`StayPlanSchema`）。宿の名前は、宿を調べたツールの結果にあるものだけを、サーバーが `lodging` に付けます。画面の旅程としおりの泊まりには、この候補を3件まで出します
- `lodging` のチェックインは、その日の日付です。同じ宿に2泊以上するときも、候補はチェックインの日の泊まりにだけ付き、続く夜の泊まりには付きません
- 主役の祭りの予定は、どれか1日に必ずあります。祭りは旅の中に1つあればよく、ほかの日は観光・移動・温泉・休みだけの日でもかまいません。日が合えば別の祭りも入れられます
- 祭りのない日の行き先は、祭りのデータとツールの結果にある場所だけを使います。足りないときは場所を作らず、「自由に過ごす時間」（`free`）の予定にして、そう書きます。`free` の予定には場所（`location`・`spotId`）を付けません
- 予定の `id` は旅程全体で重なりません
- 1日の予定は1件以上です。祭りの予定1件だけのお出かけも、そのまま旅程になります

## 食事の案

滞在の時間帯にかかる食事は、昼（`lunch`）・夜（`dinner`）ごとに案を1つ持ちます（`MealPlanSchema`）。店の予定（`type: "meal"`）として入れる食事のほかに、祭りの最中に屋台で食べるような、ほかの予定の中でとる食事もここに書きます。

| 項目      | 意味                                                                                           |
| --------- | ---------------------------------------------------------------------------------------------- |
| `slot`    | `lunch` 昼・`dinner` 夜                                                                        |
| `kind`    | `shop` 店・`stalls` 祭りの会場の屋台・`station` 駅や道中で買う・`bring` 持っていく             |
| `name`    | 店の名前か、案の短い説明                                                                       |
| `itemId`  | この食事をとる予定の `id`（店の予定、祭りの予定など）。その日の予定を指す。予定の外なら `null` |
| `spotId`  | 店の場所の ID（任意）                                                                          |
| `sources` | 出典。店と屋台の案では必須（屋台は祭りのデータの出典）                                         |

滞在の時間帯（出発の駅からの移動が着いてから、帰りの移動に乗るまで）が 11:30〜13:30 に30分以上かかれば昼、17:30〜19:30 に30分以上かかれば夜の案が要ります。

## 移動の区間と乗り換え

移動（`move`）は、手段と所要時間の目安に加えて、次を持ちます（どれも任意。古い版の旅程にはない）。

| 項目         | 意味                                                                                                                                                                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `from`・`to` | 出発・到着の場所（駅・会場・店の名前）                                                                                                                                                                                                                  |
| `purpose`    | 移動の役目。`outbound` 出発の駅から目的地の駅へ・`last_mile` 駅から祭りの会場へ（最後の移動）・`between` 寄り道どうし・`return` 帰り                                                                                                                    |
| `legs`       | 乗り換えごとの区間（手段・出発・到着・路線・所要時間の幅）。区間はつながった順に並べ、最初と最後は移動の `from`・`to` にそろえる。区間の境の場所が乗り換えの駅になる（`transferStations`）。路線は調べた結果にあるものだけを書き、分からなければ `null` |

電車・バスの移動の出典は、祭りのデータのアクセス案内か、行き方の調べで実際に読んだページだけです。

## 調べた場所の採否

周辺係と宿の係が見つけた場所は、旅程に入れたかどうかと、その理由を `considered` に残します（`ConsideredPlaceSchema`）。採ったか（`adopted`）は、予定の `spotId` と宿の候補からサーバーが決め、理由（`reason`）は旅程係が書きます。採らなかった場所は、なぜ採らなかったか（営業時間が合わない、遠い、など）を書きます。理由のない場所は不足（`research_unreviewed`）になります。

## 点検（そろっているか）

旅程を保存するとき、予定の矛盾（重なり・移動の時間・営業時間・祭りの時間・到着の余裕・帰りの最終に間に合うか）に加えて、そろっているべきものをコードで確かめます（`apps/server/src/domain/planCoverage.ts`）。足りないものは保存を止めずに `gaps` に書き、評価の点に入れます。

| 不足の種類               | 確かめること                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| `outbound_missing`       | 1日目の最初の予定が、出発の駅からの移動か                                                |
| `return_missing`         | 帰る日の最後の予定が、帰りの移動か                                                       |
| `last_mile_missing`      | 祭りの予定の前に、会場までの最後の移動（`last_mile`、または祭りの予定の `move`）があるか |
| `last_return_unknown`    | その日のうちに帰る日に、帰りの最終の時刻（出典つき）があるか                             |
| `move_endpoints_missing` | 移動に出発・到着の場所があるか                                                           |
| `transfer_unknown`       | 電車・バスの移動に、乗り換えごとの区間（`legs`）があるか                                 |
| `move_unsourced`         | 電車・バスの移動に出典があるか                                                           |
| `meal_missing`           | 滞在の時間帯にかかる昼・夜の食事の案（`meals` か食事の予定）があるか                     |
| `meal_unsourced`         | 食事の予定（店）に出典があるか                                                           |
| `research_unreviewed`    | 周辺係・宿の係が見つけた場所すべてに、採否と理由があるか                                 |

帰りの移動が帰りの最終（`lastReturn.departBy`）より後に出る旅程はエラー（`after_last_return`）として保存しません。

## 旅程の評価

保存した旅程は、評価係が観点ごとに 0〜100 で採点します（`PlanEvaluationSchema`）。観点は網羅（`coverage`）・具体さ（`specificity`）・無理のなさ（`feasibility`）・出典（`grounding`）の4つです。点検の結果からコードで出す点と、評価係（モデル）の点のうち低いほうを、その観点の点にします。評価係が動かないとき（モックやキーのないとき）は、コードの点だけで決めます（`judgedBy: "code"`）。

- すべての観点が基準（70点）に届けば合格（`passed`）
- 届かなければ、足りない観点を名指しして、経路（`route`）・周辺（`nearby`）・宿（`lodging`）の係への調べ直しの頼み（`redo`）を付け、旅程係が調べ直して作り直す。評価は1回の相談で3回まで（`maxRounds`）
- 3回で届かなければ、そのときの旅程を保存したまま、足りない点（`findings`）を使う人にそのまま伝える

採点のしかたと、評価の手法を選んだ理由は [設計判断の記録 0008](../adr/0008-plan-check-and-evaluation-loop.md) にあります。

## 宿の候補

宿の候補は、宿泊予約の API で調べた空きか、公開の Web で調べた宿のページの結果だけを持ちます（`LodgingSearchSchema`）。名前と料金をモデルに作らせないためです。

| 項目                  | 意味                                                                                                            |
| --------------------- | --------------------------------------------------------------------------------------------------------------- |
| `checkIn`・`checkOut` | チェックインとチェックアウトの日                                                                                |
| `searchedAt`          | 調べた時刻                                                                                                      |
| `provider`            | 調べた方法。`rakuten` 空室検索 API・`web` 公開の Web の調べ・`fictional` 架空の宿（開発の見本）。古い版にはない |
| `offers`              | 宿の候補（5件まで。Web の調べは3件まで）。空なら、条件に合う宿がなかった                                        |

宿の1件（`LodgingOfferSchema`）：

| 項目                | 意味                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`・`name`        | 宿の ID と名前。Web で調べた宿の ID は `web-` で始まり、名前から決める                                                                     |
| `nightlyTotalYen`   | 1泊の料金（全員分・円）。空室検索では調べた時点の最安のプランの目安。Web の調べでは空きを調べていないので `null`                           |
| `perPersonNightYen` | 宿のページに書かれた1泊1人あたりの料金の幅（円、任意）                                                                                     |
| `priceNote`         | 料金の目安の文（任意。1室の料金しか書かれていないときなど）                                                                                |
| `summary`           | 宿の特徴の要約（任意。調べた係の言葉で1文）                                                                                                |
| `bookingUrl`        | 予約のページ（http・https だけ）。Web の調べでは、読んだ宿の公式か予約サイトの宿のページ                                                   |
| `location`          | 宿の緯度・経度。分からなければ `null`                                                                                                      |
| `fromVenue`         | 会場からの直線の距離（`distanceKm`）と移動の目安（`mode`：`walk` 徒歩・`ride` バスやタクシー、`minutes` 分の幅）。コードで計算する（任意） |
| `perspectives`      | Web の調べで、この宿が挙がった観点（`venue` 会場の近く・`station` 駅の近く・`budget` 予算・`family` 家族向け。任意）                       |
| `checkedAt`         | 調べた時刻                                                                                                                                 |
| `source`            | 出典（予約サイトや宿のページ。表示が求められるクレジットは `title` に書く）                                                                |

料金と空きは予約の時点で変わることがあります。宿の候補を出すときは、調べた時刻と、そのことを必ず添えます。Web で調べた宿は空きを調べていないので、空きと料金は予約のページで確かめるよう添えます。

## 予定1つ1つの情報

| 項目                   | 意味                                                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `start`・`end`         | 予定の時間帯（HH:MM）                                                                                                                                                           |
| `type`                 | 移動・観光・食事・休憩・祭りの前の準備（到着の余裕・場所取り・申し込み）・祭り・自由に過ごす時間                                                                                |
| `name`・`location`     | 名前と、地図に打つ緯度・経度（移動の予定などでは `null`）                                                                                                                       |
| `reason`               | ここに入れた理由を1文で（例：「灯籠流しの受付は16時までなので、先に済ませておく」）                                                                                             |
| `move`                 | 前の予定からの移動の手段と時間。**時間は必ず目安**（`estimate: true`）として幅で持つ。出発・到着・役目・乗り換えの区間も持てる（[移動の区間と乗り換え](#移動の区間と乗り換え)） |
| `hours`                | 当日の営業時間                                                                                                                                                                  |
| `cost`                 | 費用の目安（無料、体験 600円 など）                                                                                                                                             |
| `festivalId`・`spotId` | 祭りや周辺の場所への参照                                                                                                                                                        |
| `sources`              | 出典。祭りと周辺の場所の予定では必須                                                                                                                                            |
| `changedInVersion`     | この予定が最後に変わった版。画面で、変わった予定に色を付ける                                                                                                                    |

**旅程には、主役の祭りの予定が必ずあります。** 祭りの開催時間を、動かせない予定として持つためです。

## 修正と差分

修正のたびに版が1つ上がり、前の版からの差分（`ItineraryDiffSchema`）を `itinerary.updated` で画面に送ります。

- 予定は版をまたいで同じ `id` を持つ。別の日へ移った予定は変わった予定にする
- 差分の `added`・`changed` は予定の `id`、`removed` は `id` と名前
- 初版の差分は `fromVersion` を 0 にする
- `verification` は決定するまで確認前。決定のとき、主役の祭りとその日の候補の確かめの結果を書く（なければそのときだけ Web で確かめる）
- 主役の祭りか、その祭りの日が変わったら、`verification` は確認前に戻る。それ以外の修正では引き継ぐ

## 組み立ての手順

祭りの時間を先に固定し、前後の空き時間を埋めます。泊まりの旅では、日ごとに同じ手順で組みます。手順 1・3・7 と 8 の点検の点はコード、2 と 4〜6 は Claude（旅程係）、8 の具体さなどの採点は Claude（評価係）が判断します。

泊まりの旅は1日ずつ書きます。旅程係は、はじめに主役の祭りの日だけを保存し、そのあと `update_itinerary` の `addDay` で1日ずつ足します。保存のたびに版が上がり、`itinerary.updated` で画面の旅程が1日ずつ増えます。検証と天気は日ごとに行い、祭りのない日の行き先は `search_nearby` を地域と日付で呼んで、その日ごとに探します。結果に場所がなければ、場所を作らず「自由に過ごす時間」にします。

1. **祭りを固定する**：開催時間の前に「到着の余裕」を足す。初期値は規模ランクで決める（XS・S：15分、M：30分、L：60分）。花火大会は場所取りがあるので30分足す
2. **調べる**：`research_trip` で、経路（行きの乗り換えと帰りの最終まで）・食事・寄り道を並べて調べる。空き時間を時間帯に分け、その時間帯で探す
3. **候補を絞る**：当日が休業の場所、営業時間が時間帯に合わない場所、こだわりのごはんが「屋台で十分」のときの店を除く（遠すぎる祭りは、この前の祭りの候補の段階で、日程のルールが除く）
4. **枠を埋める**：同行者に合うか、移動が短いか、祭りとの相性（昼に観光、夜に祭りなど）で選ぶ。滞在の時間帯にかかる昼・夜の食事は、店の予定か、屋台などの案（`meals`）を必ず持つ。周辺係・宿の係が見つけた場所は、採ったかと理由を `considered` に書く
5. **休憩を入れる**：子連れは2時間ごとに休憩を入れる。「もっとゆっくり」と言われたら予定を1つ減らし、休憩を延ばす
6. **帰りを決める**：終わった直後の混雑を避ける案（少し待つ、夕食をはさむ）を1つ出す
7. **検証する**：日ごとに、予定の重なり、営業時間の外、祭りの時間とのぶつかりがないことを `update_itinerary` で確かめる。祭りの予定は、その日に祭りが開かれるかも確かめる。そろっているか（[点検](#点検そろっているか)）も確かめる
8. **評価して直す**：保存した旅程を評価係が採点し、基準に届かなければ、足りない観点の係に調べ直しを頼んで作り直す（[旅程の評価](#旅程の評価)）

## 祭りを固定した旅程

祭りから探して決めた祭りを固定した相談（`ChatRequest.anchor`）では、`update_itinerary` が次を確かめます。計算は `apps/server/src/domain/anchorPlan.ts` です。

| 確かめること                                                 | 守られていないとき                      |
| ------------------------------------------------------------ | --------------------------------------- |
| 主役の祭り（`mainFestivalId`）がアンカーの祭りである         | 保存しない（`anchor_festival_changed`） |
| 主役の祭りの予定（`type: "festival"`）がアンカーの日にある   | 保存しない（`anchor_date_missing`）     |
| 旅程の日付が `AnchorPlan` の `startDate`〜`endDate` に収まる | 保存しない（`anchor_outside_dates`）    |
| `included` の場所が旅程にある                                | 警告（`anchor_visit_missing`）          |
| 組み始める前の確かめで中止と分かった祭りの旅程でない         | 保存しない（`anchor_cancelled`）        |

`included` の場所は、予定の名前・泊まる地域に県の名前があるか、予定の場所にいちばん近い代表の位置がその県か、別の祭りの予定の開催地がその県かで見ます。

`AnchorPlan` の計算で決めていることは次のとおりです。

- **都道府県の代表の位置**：県庁所在地の中心駅の位置（`apps/server/src/domain/prefecturePoints.ts`）。出典は [駅の位置のデータ](../stations.md)（国土数値情報の鉄道データ）。その県の祭りの会場は使いません
- **移動の時間**：`travelEstimate` の見積もりの幅の真ん中で比べます
- **出発の駅の位置が分からないとき**：祭りと同じ県のほかは判断できないので `maybe` にし、旅程係に渡します。出発の駅からの所要時間も分からなければ、`minNights` は `null` です
- **祭りの日の使える時間**：開始の時刻があれば、朝7時から開始までと、終わりから0時まで。開始の時刻がなければ、1日に動ける時間から滞在を除いた半分ずつです

## 日程のルール

- 日程は守る条件。候補にするのは、希望日（期間）に開く祭りだけ。今日より前の日は除く
- 前後2週間の祭りも探し、日程のほかの条件に合えば「この祭りならやっています」として、「ご希望の日の3日後（8月19日）に開きます」のように、ずれを添えて紹介する（[条件の守り方](agents.md#条件の守り方)）
- 「来週末」のような期間の希望も同じルールで扱う。前側の2週間が過去にかかれば、自動的に今日以降に絞られる
- 日帰り（0泊）は、出発の駅から会場までの片道の所要時間で絞る。上限は聞き取った `maxTravelMinutes`（1時間・2時間・3時間以内など）、言われていなければ150分。泊まりの旅は所要時間で絞り込まない
  - 上限を言われたら必ず守る条件で、上限に収まると分かっている祭り（`travelFit: "within"`）だけを候補にする。駅の位置からの見積もりの幅が上限をまたぐ祭り（`uncertain`）と、所要時間が分からない祭り（`unknown`）は候補にせず、外れている点を添えて残す
  - 言われていなければ（150分の初期値）、明らかに超える祭り（`over`）だけを除き、境目の祭りと分からない祭りは残して結果の注意（`notes`）で伝える
  - 候補には、条件に照らした値（`travel`：片道の所要時間の幅・根拠・上限・比べた結果）を付け、画面に「出発の駅から片道およそ1時間50分〜2時間30分（目安）」と出す
- 所要時間はコードで計算する（`apps/server/src/domain/dateWindow.ts` の `travelMinutesFrom`）。祭りのデータのアクセス（`access`）の、主要駅から最寄り駅までの所要時間（`fromHubs`）のうち出発の駅に当たるものに、最寄り駅から会場までの徒歩（`stations`）を足した目安の幅で、幅の上側が上限以下なら収まるとする
- 出発の駅が `fromHubs` にない祭りは、駅の位置から見積もる（`apps/server/src/domain/travelEstimate.ts`）。見積もりの下限は新幹線なみの速さで計算するので、遠い地方の祭りでも下限が上限を下回ることがある。そのため、上限を言われたときは見積もりの上限（幅の大きい方）が収まる祭りだけを候補にする

テストケースは [テストの仕様](testing.md#日程のルールのテストケース) にあります。

## こだわりの効果

こだわりは4項目で、どれも1つを選ぶ切り替えです（`PreferencesSchema`）。

| 項目                 | 選択肢                                                            | 初期値     |
| -------------------- | ----------------------------------------------------------------- | ---------- |
| だれと（`party`）    | 大人だけ（`adults`）／子連れ（`kids`）／シニアと一緒（`seniors`） | 大人だけ   |
| どんな場所（`spot`） | 定番どころ（`classic`）／おまかせ（`auto`）／穴場（`hidden`）     | おまかせ   |
| ごはん（`food`）     | 屋台で十分（`stalls`）／地元の店も楽しむ（`local`）               | 屋台で十分 |
| 移動（`move`）       | 電車（`train`）／車（`car`）                                      | 電車       |

| こだわり         | 旅程への効果                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| 子連れ           | 2時間ごとに休憩を入れる。トイレとベビーカーの情報を出す。夜は冷え込みと帰りの混雑を避ける組み方にする |
| シニアと一緒     | 歩く距離を短くし、座れる場所を優先する                                                                |
| 定番どころ       | 周辺の主な観光地と人気の店を優先する                                                                  |
| 穴場             | 祭りも周辺も、大手の観光サイトに載っていない場所を優先する                                            |
| おまかせ         | 定番と穴場を半分ずつ混ぜる                                                                            |
| 地元の店も楽しむ | 祭りの前後に、郷土料理や地元の店での食事を予定として入れる                                            |
| 屋台で十分       | 屋台を食事の時間として扱い、店の予定は入れない                                                        |
| 車               | 駐車場と交通規制を先に確かめる。駐車場のない祭りでは、電車をすすめる注意を出す                        |

「定番」と「穴場」の判断には、祭りのデータの知名度（`popularity`）を使います。
