# テストの仕様

## テストの層

| 層             | 道具       | 対象                                                                                                    |
| -------------- | ---------- | ------------------------------------------------------------------------------------------------------- |
| スキーマ       | Vitest     | 3つの壁を型で守れているか（下の表）、サンプルの相談がスキーマに合うか                                   |
| 決まった計算   | Vitest     | 日程のルール、到着の余裕、こだわりの効果、旅程の検証（`apps/server/src/domain/`）                       |
| ツールとストア | Vitest     | ツールの入出力、祭りのデータの読み込み、SSE のイベントからストアへの変換                                |
| しおり         | Vitest     | view-model、見た目とページの選び方、エスケープ、PDF の上限（Chromium があれば PDF も作る）              |
| 3D と遊び      | Vitest     | スタッフの動きの段取り、旅人の操作と仕掛け、道探し（`apps/web/src/scenes/`）                            |
| ログインと保存 | Vitest     | 保存の口（メモリ。Firestore の版は `FIRESTORE_EMULATOR_HOST` があるときだけ）、旅の API、画面のログイン |
| 画面の通し     | Playwright | 下の「画面の通しテスト」                                                                                |
| データ         | スクリプト | `data/festivals/` のすべてのファイルをスキーマで検証する                                                |

### 画面の通しテスト

Playwright で、デスクトップ（1440×900）とスマートフォン（Pixel 7）の2つの大きさで回します（`apps/web/e2e/`）。

| ファイル                | つなぐ先                     | 確かめること                                                                                                          |
| ----------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `consultation.spec.ts`  | 接客サーバー（モックモード） | 相談からしおりまで、豆知識係とクイズ、キーボードだけの操作、動きを減らす設定の 2D、英語への切り替え                   |
| `scene3d.spec.ts`       | 接客サーバー（モックモード） | 外観から入店、スタッフの動き、旅人を歩かせて仕掛けを使いコンシェルジュに話す、WebGL がないときと動きを減らす設定の 2D |
| `server-stream.spec.ts` | テストの中で SSE を返す      | 途中で切れたときの送り直し、エラーを文字列で出すこと、英語の画面の文言                                                |
| `server-wiring.spec.ts` | テストの中で API を返す      | 合言葉、相談が見つからないときの新しい相談、しおりの URL                                                              |

テストは**架空の祭り**で書きます。テスト用の祭り・旅程・出典は `@matsuri-ikoka/schema/testing` にあり、URL は例示用のドメイン（`example.com`）です。

## 壁を守るテスト

| 壁               | テストで確かめること                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 情報             | 出典のない祭り・開催回・小話はスキーマで不正になる。分かっているアクセス情報や作法に出典がなければ不正になる                   |
| 作法             | 作法のない祭りは不正になる。作法の項目を省略すると不正になる（分からないなら `"unknown"` と書く）                              |
| 計画             | 主役の祭りの予定がない旅程は不正になる。移動時間を目安でない値として持てない。日程のルール・到着の余裕・旅程の検証の単体テスト |
| 祭りとのつながり | 掲載停止（`optOut`）の祭りは検索に出ない                                                                                       |

## 利用者ごとの分離のテスト

ほかの人のデータに触れないことは、[利用者ごとの分離](account.md#利用者ごとの分離) の決まりごとに、次のテストで確かめます。

| テスト                           | 確かめること                                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `routes/policy.test.ts`          | すべての経路が認可の決まりを宣言している。宣言のない経路があると起動しない。文書の表とそろっている                                    |
| `routes/isolation.test.ts`       | 利用者 A のものを、利用者 B・ログインなし・偽のトークンで、経路ごとに読めず変えられない。3人が同時に相談しても SSE と旅程が混ざらない |
| `routes/logging.test.ts`         | 発言の本文・位置・自由記述・トークン・合言葉が、失敗の経路でもログに残らない                                                          |
| `storage/owner.test.ts`          | 持ち主を決めずに利用者のデータを読み書きする呼び出しが、型の検査で落ちる                                                              |
| `storage/contract.ts`            | 保存の口の決まり。メモリと Firestore（エミュレーター）の両方で回す                                                                    |
| `storage/firestoreRules.test.ts` | セキュリティルールの内容。エミュレーターがあれば、ブラウザからの読み書きが実際に断られること                                          |
| `agent/claudeRunner.test.ts`     | 会話の記録は、その相談が受け取ったものからだけ続ける                                                                                  |

パスは `apps/server/src/` から書いています。

## 日程のルールのテストケース

`searchFestivalDates`（`apps/server/src/domain/dateWindow.ts`）の単体テストです。表の移動時間の上限はテストで渡す値で、日帰りの既定の上限は片道150分です。ルールは [旅程の仕様](itinerary.md#日程のルール) にあります。

| #   | 今日 | 希望                           | 当日の祭り                     | 期待する探す範囲           | 期待する結果                                                   |
| --- | ---- | ------------------------------ | ------------------------------ | -------------------------- | -------------------------------------------------------------- |
| 1   | 8/3  | 8/16                           | あり                           | 8/16（補う分は 8/3〜8/30） | 8/16 の祭りが先頭。前後2週間の祭りも、ずれを付けて後ろに並べる |
| 2   | 8/3  | 8/16                           | なし                           | 8/3〜8/30                  | ずれの日数つきで返す                                           |
| 3   | 8/8  | 来週末（8/15〜16）             | なし                           | 8/8〜8/30                  | 今日より前は出ない                                             |
| 4   | 8/3  | 8/4                            | なし                           | 8/3〜8/18                  | 8/2 以前は出ない                                               |
| 5   | 8/3  | 8/16                           | 開催が確認できていない祭りだけ | 8/16 のみ                  | 「未確認」と表示し、確定した旅程には入れない                   |
| 6   | 8/3  | 8/16（日帰り、移動の上限90分） | 遠くの祭りだけ                 | 8/16 から前後2週間へ広げる | 遠くの祭りは除かれる                                           |

日帰りの所要時間の上限（`maxTravelMinutes`）のテストも同じファイルにあります。片道の目安の上側が上限を超える祭りは除き、所要時間の分からない祭りは残して後ろに並べ、泊まりの旅では絞り込みません。

条件の守り方は `apps/server/src/domain/searchConditions.test.ts` で確かめます。架空の駅の位置から、直線で約220km離れた架空の祭りが、片道3時間以内と言われた日帰りで、見積もりの幅が上限をまたぐために「境目」として候補に残っていたこと（これまでの絞り込み）を再現し、条件の検査では候補にせず外れた理由を残すこと、希望の日程から外れた祭りを候補にしないこと、条件を1つだけ外せば出る祭りの選び方、次の手を変えた条件で数え直して見つかる手だけを出すこと、探す回数の上限を試します。`searchFestivalDates` の表の結果は、条件の検査の前の並びです（前後2週間の祭りは、候補ではなく「この祭りならやっています」になります）。

行き先の守り方は `apps/server/src/domain/destination.test.ts` で確かめます。隣接する県の表が両方の県から対称になっていること、地方の名前を都道府県に直すこと、選んだ地域 → 隣接する県 → 全国の順に広げ、了承を得ていない段階では候補を出さずに問いを返すことを、架空の祭りの開催地の県だけを変えて試します。

## 受け入れの基準

相談からしおりまでを通して、次をすべて満たしたら受け入れます。相談する人は、祭りのある町に住んでいない人を想定します。

**祭りの候補**

- [ ] 日付・出発地・移動手段・同行者の条件だけで（祭りの名前を言わなくても）、条件に合う祭りが候補に出る
- [ ] 希望の日程・片道の所要時間・行き先から外れる祭りは、候補に出ない
- [ ] 条件に合う祭りがなければ「条件に合う祭りは見つかりませんでした」と出て、条件を1つだけ外せば出る祭り（外れている点つき）と、次の手のボタンが出る。ボタンを押すと、変えた条件で探し直す
- [ ] 祭りの日時と雨天の扱いが、出典つきで表示される。開催が確認できていない祭りには「未確認」と出る

**旅程**

- [ ] 移動手段に合った経路が出て、駐車場の有無と交通規制が書かれている
- [ ] 会場への到着が、規模ランクと祭りの種類のルールどおりの余裕をとっている
- [ ] 祭りの前の予定に、当日が休業の施設や、営業時間の外の予定が入っていない
- [ ] 移動時間に「目安」と付いている
- [ ] 夜に終わる祭りの旅程には、帰りの混雑の避け方が入っている
- [ ] 子連れのときは、休憩・トイレ・帰りの混雑・夜の冷え込みに触れている
- [ ] 「もっとゆっくり」と頼むと予定が1つ減り、変わった予定が色で示される
- [ ] こだわりを切り替えると、祭りの前後の予定が入れ替わる

**確定としおり**

- [ ] 「決定」のあと、公式情報での再確認の結果が出てから、しおりが開く
- [ ] しおりに、見どころ・地元の味・作法・持ち物・雨の日の案・出典がある
- [ ] 「地元の店も楽しむ」を選んでいれば、地元の店での食事が予定に入っている

**店内と待ち時間**

- [ ] スタッフが調べている間、店内のスタッフが持ち場へ動き、吹き出しが出る
- [ ] 待っている間は、出典つきの祭りの小話が切り替わる
- [ ] 祭りのカードに、おすすめポイントと祭りの特徴が出る
- [ ] しおりが完成すると演出が入る
- [ ] 3D を使わなくても、同じ情報が文字で読める
