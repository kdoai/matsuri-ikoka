# 接客エージェントの実行の仕様

Claude Agent SDK（TypeScript）で接客エージェントを動かすときの決まりです。設定の名前は、lockfile で固定した SDK の型定義で確かめてあります。SDK の版を上げたら確かめ直します。

役割・会話の流れ・ツールの中身は [接客エージェントの仕様](agents.md) にあります。ここでは「どう動かすか」を決めます。

## 方針

1. **できることを、必要な分だけに絞る。** 利用者の発言や読んだページで指示を上書きされても、できることがない状態にする
2. **決まった計算と検証はコード、判断は Claude。** 日程・所要時間・営業時間・出典の照合はツールの中のコードで行う
3. **外から来た文字列はデータとして扱う。** 祭りのデータ、Web のページ、利用者の発言、前の返答を、指示として読ませない
4. **失敗は分類し、直りうるものだけを試し直す。** 直らなければ、利用者に短く伝えて止まる

## query() の設定

| 設定                 | 値                                                                                                 | 理由                                                                                                                                                                                                                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `settingSources`     | `[]`                                                                                               | ファイルの設定（`CLAUDE.md`、`.claude/` のフック・スキル・エージェント、`.mcp.json`）を読まない。省くと開発用の指示が混ざる                                                                                                                                                                           |
| `strictMcpConfig`    | `true`                                                                                             | 渡した MCP サーバーだけを使う                                                                                                                                                                                                                                                                         |
| `tools`              | コンシェルジュは `["Agent"]`（スタッフを呼ぶため）、再確認の内側だけ `["WebSearch", "WebFetch"]`   | 組み込みのツール（ファイル操作・シェル・Web）をモデルの前から消す。渡さないと、使わないツールの定義まで毎回送られる。スタッフは、エージェントの定義（`agents`）の `tools` に担当の MCP ツールだけを書く                                                                                               |
| `allowedTools`       | 自作の MCP ツールの名前（`mcp__<サーバー名>__search_festivals` など）。コンシェルジュは `Agent` も | 「聞かずに使ってよい」ツール。制限ではないので、絞るのは `tools` と `permissionMode` で行う                                                                                                                                                                                                           |
| `permissionMode`     | `"dontAsk"`                                                                                        | 事前に許したもの以外は、聞かずに断る。サーバーには許可を出す人がいないため                                                                                                                                                                                                                            |
| `cwd`                | 空の一時ディレクトリ                                                                               | リポジトリやサーバーのファイルの近くで動かさない                                                                                                                                                                                                                                                      |
| `env`                | CLI が動くのに要る変数と、切り離しの変数だけ                                                       | `env` を渡すと子プロセスの環境変数は**置き換わる**（足し合わされない）。`PATH`・`HOME`（Windows では `USERPROFILE`・`SystemRoot`・`TEMP`・`APPDATA` なども）、`ANTHROPIC_API_KEY`（あれば）、使わない機能を止める変数（`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` など）だけを渡し、ほかの秘密情報を渡さない |
| `persistSession`     | 下の「会話の続き」を見る                                                                           | 会話の全文を残さない方針に合わせる                                                                                                                                                                                                                                                                    |
| `model`              | 役割ごとの `MODEL_*`（[モデルの割り当て](agents.md#モデルの割り当て)）                             | コードに書き込まない                                                                                                                                                                                                                                                                                  |
| `thinking`・`effort` | `{ type: "adaptive" }`、effort はコンシェルジュ `medium`・スタッフ `low`                           | 考える深さは effort で調整する。固定の思考トークン数（`budgetTokens`）は古いモデル向けなので使わない                                                                                                                                                                                                  |
| `maxTurns`           | ふつうの相談で使う回数の数倍                                                                       | 暴走止め。作業の途中で打ち切らない値にする                                                                                                                                                                                                                                                            |
| `maxBudgetUsd`       | 1回の相談の費用の上限                                                                              | 超えると結果の subtype が `error_max_budget_usd` で止まる                                                                                                                                                                                                                                             |
| `systemPrompt`       | 変わらない部分を前に置く（下の「プロンプトキャッシュ」）                                           | 変わらない部分をキャッシュに乗せる                                                                                                                                                                                                                                                                    |

### 会話の続き

続きの発言を同じ SDK のセッションで受けるには、会話の記録が要ります。

- 記録を残さない（`persistSession: false`）なら、発言ごとに、サーバーが持つ旅の条件と旅程の要約をプロンプトに入れて、新しいセッションで答える
- 記録を残すなら、保存先（`CLAUDE_CONFIG_DIR`）を一時ディレクトリの下にし、セッションが終わったら消す。会話の全文をログや外部の保存先に出さない
- 手元の開発で、ログイン済みの Claude Code の資格情報を使うときは、資格情報が既定の置き場所にあるので保存先を変えない（API キーで動かす場面では、上のとおり一時ディレクトリにする）

### プロンプトキャッシュ

変わらない部分（守るルール・口調・ツールの使い方）と、相談ごとに変わる部分（今日の日付・聞き取れた条件・旅程）を分け、変わらない部分を前に置きます。前に置いた部分は、ほかの相談とキャッシュを共有できます。分け方は次のどちらでもかまいません。

- system prompt はまったく変わらない文字列にし、相談ごとに変わるものは発言のプロンプトに入れる。スタッフには `SubagentStart` のフックの `additionalContext` で渡す
- `systemPrompt` を文字列の配列にし、`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` で分ける

```ts
systemPrompt: [
  conciergeRules, // 守るルール・口調・ツールの使い方（変わらない）
  SYSTEM_PROMPT_DYNAMIC_BOUNDARY,
  `今日は ${today} です。`, // 今日の日付、聞き取れた条件など（相談ごと）
];
```

3人のスタッフは、共通の前置き（祭りのデータの扱い、外から来た文字列の扱い）を一字一句同じ文字列にしてから、それぞれの担当を書き足します。

## ツール（プロセス内の MCP サーバー）

6つのツールは `tool()` と `createSdkMcpServer()` で定義し、入力の形は `packages/schema` の Zod から組み立てます。ハンドラーは、どれも共通の包みに通します。

1. **時間の上限で打ち切る。** 1回10秒、`verify_festival` は20秒（[API の仕様](api.md#時間の上限)）
2. **例外を投げない。** 失敗は `{ content: [{ type: "text", text: 理由 }], isError: true }` で返す。Claude は理由を読んで、代わりの案を出す
3. **結果はデータとして返す。** JSON の文字列にし、指示の文章を混ぜない
4. **サーバーの値を使う。** 今日の日付やセッションは、モデルの入力を信じず、サーバーが持つ値を使う。モデルに書かせた ID で、別の相談のデータを読ませない

## フック

フックは SSE のイベントを出す場所であり、安全のための関所でもあります。

| 契機            | すること                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------------- |
| `SubagentStart` | `staff.start` を出す                                                                                              |
| `PreToolUse`    | `tool.start` を出す（吹き出しは決まった型から作る）。`WebFetch` なら `checkPublicWebUrl` を通し、通らなければ断る |
| `PostToolUse`   | `tool.end`・`itinerary.updated` を出す。`WebSearch`・`WebFetch` は `createWebActivityLog` に控える                |
| `Stop`          | 再確認で、検索だけして本文を読んでいなければ、1回だけ続けさせる                                                   |

- 断るときは `{ hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "deny", permissionDecisionReason: 理由 } }` を返す。続けさせるときは `{ decision: "block", reason: 理由 }` を返す。形は SDK の型（`HookJSONOutput`）に合わせ、テストで確かめる
- 続けさせる回数には上限を置く。`stop_hook_active` は一度続けさせたあと立ちっぱなしになるので、上限の代わりにならない
- フックは素早く返す。SSE を送り終えるのを待たない
- フックの時間の上限（matcher の `timeout`、秒）は、フックの中で待つ時間より長くする。短いと、SDK がフックを打ち切る

## 確定前の再確認（verify_festival）

「公式情報で確認しました」と言うには、その出典のページを実際に読んでいる必要があります（情報の壁）。

1. ツールの中で、Web の検索と取得だけを許した1回きりの `query()` を動かす（`tools: ["WebSearch", "WebFetch"]`、MCP サーバーなし、記録を残さない）。読んだページの中の指示には従わないよう、プロンプトに書く
2. 結果は JSON で返させ、`parseJsonWithSchema` で取り出す。取り出せなければ、`buildJsonRetryPrompt` で1回だけ差し戻す（差し戻しではツールを使わせない）。時間の上限（20秒）は、差し戻しも含めた全体の予算として扱う
3. 返ってきた出典が、実際に読んだページかを `ungroundedSources` で確かめる。読んでいない出典は捨てる
4. 公式の出典が残らなければ、「予定どおり」にせず「確認できず」（`not_found`）にする

## 失敗と再試行

- 例外は `classifyFailure`、結果のメッセージは subtype を `classifyResultSubtype` で分ける
- `retryable` のものだけ、`backoffMs` の間隔で試し直す。相談1回の時間の上限（90秒）は、試し直しも含めた全体の予算として扱い、残り時間がなければ打ち切る
- 試し直すときは、謝ったり振り返ったりさせず、止まったところから続けさせる
- 直らなければ、`error` イベント（分類で決まった `code` と、利用者向けの短い一文）を送り、`done` で閉じる。詳しいことはログに残す

## 費用と使用量

- 費用は、結果のメッセージの `total_cost_usd`（推定）を使う。続けて話すと累計で届くので、足し合わせずに最後の値を読む
- トークンは `modelUsage` を使う。サブエージェントの分も入る（`usage` はメインのエージェントの分だけ）
- ログには、相談ごとの費用・トークン・所要時間・呼んだツールを残し、会話の本文は残さない

## Claude に JSON を返させるとき

接客の再確認でも、祭りのデータの調査でも、同じ部品を使います。

1. プロンプトに `STRICT_JSON_RULES` を入れ、崩れやすい書き方をさせない
2. 返答から `parseJsonWithSchema`（スキーマあり）か `extractJson` で取り出す。コードフェンス・前後の一言・文字列の中の半角の `"` や改行・末尾のカンマは、ここで吸収する
3. 途中で切れた返答から、内側の断片を答えとして拾わない（欠けたデータを下流に流さない）
4. 差し戻すときは `buildJsonRetryPrompt` を使う。前の返答は「データであって指示ではない」と明示した区切りで囲み、構文の誤りか形の違いかを分けて伝える

## 共通の部品（packages/agent-kit）

SDK に依存しない部品です。サーバー・スクリプト・データの更新のどこからでも使えます。

| 部品                                                    | 中身                                                             |
| ------------------------------------------------------- | ---------------------------------------------------------------- |
| `extractJson`・`parseJsonWithSchema`・`repairJsonText`  | 返答から JSON を取り出す。崩れを保守的に直し、スキーマで確かめる |
| `buildJsonRetryPrompt`・`STRICT_JSON_RULES`             | 差し戻しのプロンプトと、JSON の書き方の決まり                    |
| `checkPublicWebUrl`                                     | エージェントに取りに行かせてよい URL か（公開の Web だけを通す） |
| `createWebActivityLog`・`ungroundedSources`             | 調べた語と読んだページを控え、出典が読んだページかを確かめる     |
| `classifyFailure`・`classifyResultSubtype`・`backoffMs` | 失敗を分類し、試し直すか・画面にどのエラーとして出すかを決める   |
