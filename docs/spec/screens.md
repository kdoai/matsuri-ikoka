# 画面の仕様

## 画面の一覧

画面は4つです。相談から旅程の修正までは、店の画面1枚の中で済ませます。

1. **店の外観**：タイトルと「入店する」ボタン。すぐに相談を始められる入り口
2. **店の画面**：画面いっぱいの 3D の店内に、会話の窓・旅の案内・旅程のパネルを重ねる。ゲームの画面の中で話しかけるように相談を進める
3. **祭りの候補**：店内に重ねて出す祭りのカード。選ぶと消えて、旅程のパネルに旅程が出る
4. **旅のしおり**：確定したあとに全画面で開く。URL で共有でき、印刷できる

### 店の画面の並び

店の画面はいつも店内が主役で、相談に要るものを周りに重ねます。

| 場所 | 置くもの                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------- |
| 上   | ロゴ、場面のタブ（旅程の案内・祭りの候補・旅のしおり・確認）、丸いボタン（お知らせ、旅のこだわり、設定、使い方） |
| 中央 | お客さんの目の高さから見た店内。カウンターの前に旅人、奥にスタッフ。旅人の横の「Ⓐ 話す」で返事を書ける           |
| 右上 | 旅の案内のカード（旅程の名前、日付、出発の駅、主役の祭りの見どころ、次にすること）と、道のりの小さな地図         |
| 下   | 会話の窓。話し手の顔の絵と名札、いまの一言、返事の欄                                                             |
| 左下 | 旅の日と出発の駅                                                                                                 |
| 右下 | ボタンの案内（Ⓧ 旅程詳細・Ⓨ 地図・＋ メニュー）。キーボードの A・X・Y・M でも同じことができる                    |
| 右   | 旅程のパネル（旅程・地図・出典）。開くと右上の案内と入れ替わる                                                   |

- お知らせ（会話の記録）では、これまでのやりとりと、スタッフ全員のようすを文字で読める。会話の窓に出ない作業の記録が増えると、印が付く
- 旅程のパネルの「旅程」は、「1日目」のカードに予定のアイコンを矢印でつないで1日の流れを見せ、その下にくわしい予定と道のりの地図を置く。組み直したら「更新！」の札を貼る
- スマートフォンでは、場面のタブとボタンの案内をメニューにまとめ、旅の案内・小さな地図・日付は出さない（旅程のパネルで読める）。旅程のパネルは画面の上に重ねる

## 画面ごとの要素

| 画面       | 要素                             | 表示する情報                                                                       | 使うイベント                                       |
| ---------- | -------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| 店の外観   | タイトル、店の外観、入店のボタン | 「小さな町の祭りの旅行代理店」の一言                                               | なし                                               |
| 店         | 旅の案内のカード、日付           | 日付、出発地、旅程の名前、主役の祭りの見どころ、次にすること。読み取れた順に埋まる | `done`、`itinerary.updated`                        |
| 店         | 店内のスタッフ                   | 4人の位置と動き、吹き出し                                                          | `staff.start`、`tool.start`、`tool.end`            |
| 店         | 会話の窓、お知らせ               | コンシェルジュの返答、利用者の発言、作業の記録                                     | `message.delta`、`tool.start`、`tool.end`          |
| 祭りの候補 | 祭りのカード（最大3枚）          | 下の「祭りのカード」の項目                                                         | `tool.end`（`search_festivals`）                   |
| 店         | 旅程のパネル「旅程」             | 1日の流れ、時刻、予定の名前、理由、移動の目安。変わった予定は色つき                | `itinerary.updated`                                |
| 店         | 旅程のパネル「地図」             | 予定の場所のピンと順番の線。会場は大きなピン                                       | `itinerary.updated`、`tool.end`（`search_nearby`） |
| 店         | 旅程のパネル「出典」             | 使った出典の一覧と確認した日、確度                                                 | `itinerary.updated`                                |
| 旅のしおり | 紙面（下の節）                   | 旅程、見どころ、地元の味、作法、注意、出典                                         | `festival.verified` のあとに開く                   |

確度のバッジの色と意味は [データの仕様](data.md#1-出典は必須) にあります。

## 祭りのカード

祭りの候補は、祭りごとの特徴とおすすめポイントがひと目で分かるカードにします。どれも祭りのデータと候補の項目から出し、その場で文章を作りません。祭りのデータがまだ届いていないときは、候補の項目だけで出します。

- **紋章の帯**：祭りの種類（灯籠・山車・踊りなど）の紋章と色、祭りの名前、希望日からのずれ
- **日時と場所**：日付と時刻、会場、確度のバッジ。未確認なら、そのことをはっきり書く
- **おすすめポイント**：見どころ（最大3つ）と、条件に合う理由
- **ここでしか**：祭りの小話を1つ（出典つき）
- **この祭りの特徴**：規模と穴場度を目盛りで、加われるか・屋台・地元の味を短い言葉で
- **出典**と、情報の訂正・掲載停止の窓口
- 「この祭りにする」を押すと、旅程を組み始める

## 旅のこだわり

条件は会話でも伝えられますが、よく使うものはタップで選べるようにします。4項目に絞り、どれも1つを選ぶ切り替えです（選択肢は [旅程の仕様](itinerary.md#こだわりの効果)）。選び直すと、旅程係だけが動いて旅程を組み直します。

- こだわりは、上の丸いボタン「旅のこだわり」から開く小さな切り替えにする。別の画面にしない
- 会話で「子どもと」と言えば「子連れ」が選ばれる。タップと会話のどちらで伝えても同じ結果になる（`done` の `preferences` で画面に返す）
- 日付と出発地は会話で聞く。選択肢にしない
- 切り替えた直後は、変わった予定だけを色で示す

## 待ち時間の見せ方

エージェントが考えている時間も、楽しめる時間にします。スタッフが持ち場へ動いて作業するようすを見せ、待っている間は祭りの小話を出します。小話は、利用者が選ばなかった祭りにも光を当てます。

- スタッフの動きと吹き出しは、フックのイベントから決まる。Claude には書かせない
- 候補が出ると祭りのカードが開き、旅程が変わると旅程のパネルに「更新！」の札が貼られる
- 再確認が通ると「旅のしおり完成」の演出が入る

### 祭りの小話

- スタッフが調べている間、画面の端に「知ってた？」のカードを数秒ごとに切り替えて出す
- 調べている間は、探している地域の祭りの小話。候補が出たあとは、その祭りの小話に切り替える
- 小話は祭りのデータの `trivia`（60字以内、出典つき）から出す。その場で Claude に作らせないので、待ち時間が増えず、誤りも入らない
- カードをタップすると、その祭りを候補に加えられる

### 祭りのクイズ

- 10秒以上待ちそうなときだけ、2択のクイズを1問出す（例：「この祭りの屋台の名物はどっち？」）
- 問題と選択肢は祭りのデータの項目から組み立てる。正解すると、しおりにスタンプが1つ増える
- 答えなくても進む。結果が出たら自動で閉じる

### 手ざわりと音

- スタッフの吹き出しは短く、キャラクターらしい口調にする
- 効果音は太鼓、拍子木、はんこの3種類だけ。音は最初は切っておき、ボタンで鳴らせるようにする
- 演出は1回 0.5〜1.5 秒に収め、何度見ても邪魔にならない長さにする
- 動きを減らす設定（`prefers-reduced-motion`）のときは、演出を控えめにし、2D の表示を主にする

## 旅のしおり

しおりは A4 縦の紙面で、画面で開く HTML と、印刷や保存に使う PDF を同じテンプレートから作ります。半日のお出かけは4ページほど、泊まりの旅は日ごとにページが増えます（6泊7日まで）。表紙の絵と色は祭りの種類と季節で決まり、スタッフと旅人の絵が各ページに出ます。中身・ページの並び・素材・PDF の作り方は [旅のしおりの仕様](shiori.md) にあります。

1. **表紙**：旅の名前、旅の長さ、日にち、同行者、主役の祭り、天気、公式の情報で開催を確かめた印
2. **旅の全体**（3日以上の旅）：日ごとの予定と泊まる地域
3. **祭りの紹介**：祭りの名前、日時、場所、規模、見どころ3つまで、小話、その土地の味、アクセス
4. **日ごとの流れ**：時刻つきの予定と、それぞれの「ここに入れた理由」、移動の目安、泊まる地域、雨の日の案
5. **はじめての方へ**：ルールとマナー、服装、持ち物、危険度、見学のみか加われるか、写真を撮ってよいか。分からない項目は「分からない」と書く。交通規制・駐車場・荒天のときの注意もここにまとめる。日本語と英語の両方で出す。行く人の不安と、「しきたりを守ってほしい」という主催者の不安の両方に応えるページなので、祭りの側のお願い（立ち入ってはいけない場所、撮ってはいけない場面など）をはっきり書く
6. **持ち物のチェックリスト**：祭りのデータの持ち物と服装、旅程のメモ、いつもの持ち物
7. **スタンプ帳とメモ**
8. **出典**：使った情報源の URL と確認した日。「当日は公式の情報で最終確認を」の一文

## 使いやすさ

- 祭りのデータとモデルの文章は、必ず文字列として表示する。HTML として埋め込まない
- 3D に出す情報（スタッフの作業、吹き出し、進み具合）は、すべて文字でも読める
- 屋外のスマートフォンでも読める、文字の濃さと大きさにする
- 地図は Leaflet と OpenStreetMap のタイルを使い、帰属の表示を必ず出す
- 日本語と英語を切り替えられる。文言は小さな辞書のファイルで持つ

## 3D の店内

3D の店内は、状態の見た目の層です（[ADR 0003](../adr/0003-3d-as-a-view-layer.md)）。モデルとモーションはすべて新しく作り、既存のゲームやキャラクターに似せません。

| 項目       | 仕様                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 雰囲気     | 丸みのあるローポリ、やわらかい色、トゥーン調                                                   |
| 店の外観   | 小さな商店街の一角。のれん、提灯、祭りのポスター。入店のときにカメラが寄る                     |
| 店内       | 1部屋。カウンター、資料棚、地図の壁、時刻表、祭りのポスター                                    |
| スタッフ   | 4人。共通のリグを使い、法被の色と小物（眼鏡、地図、時刻表、はんこ）で見分ける                  |
| モーション | 待機、歩く、作業（めくる・指さす・見上げる）、うなずく、話す、はんこを押す。各 2〜3 秒のループ |
| 動きの制御 | ストアの状態で切り替わる（待機 → 持ち場へ歩く → 作業 → 戻る）。持ち場の位置は固定              |
| 吹き出し   | 3D の上に HTML を重ねて出す。文章はフックの決まった型から作る                                  |
| カメラ     | 斜め上から見下ろす固定の視点。入店のときと、しおりの完成のときだけ動く                         |
| 照明       | 焼き込みの照明と、提灯の弱い光。リアルタイムの影は使わない                                     |
| 性能       | 60fps を目標にする。店内全体で5万三角形以下、GLB の合計 5MB 以下、テクスチャは1辺 1024px 以下  |

モデルは Blender で作り、GLB で書き出して React Three Fiber で読み込みます。作るためのスクリプトは `assets/3d/` に置きます。
