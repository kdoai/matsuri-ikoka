# 画面の仕様

## 画面の一覧

画面は4つです。相談から旅程の修正までは、店の画面1枚の中で済ませます。

1. **店の外観**：タイトルと「入店する」ボタン。すぐに相談を始められる入り口
2. **店の画面**：画面いっぱいの 3D の店内。表示を「探索」「会話」「計画」の3つに分け、そのとき要るものだけを重ねる。ゲームの画面の中で話しかけ、選択肢を選んで相談を進める
3. **祭りの候補**：店内に重ねて出す祭りのカード。選ぶと消えて、旅程のパネルに旅程が出る
4. **旅のしおり**：確定したあとに全画面で開く画面の中のしおり（1枚の紙面、ブラウザで印刷できる）。共有の URL（`/shiori/<旅程の ID>`）では、サーバーが作る A4 のしおり（HTML と PDF、下の「旅のしおり」）を開ける

### 店の画面の並び

店の画面はいつも店内が主役です。表示を3つの場面に分け、探索するときは探索、話すときは会話、旅を計画するときは詳細だけに集中できるようにします。

| 場面 | 出すもの                                                                                                                                                                                                                                                                                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 探索 | 左上にロゴと日付の小さな札（旅の日と出発の駅）。右上に丸いボタン（お知らせ、旅のこだわり、設定、使い方、ログインと自分の旅）。右下に小さな操作の案内（Ⓧ 旅程詳細・Ⓨ 地図・Ⓜ メニュー）。下に小さな「話しかける」のボタン。会話の窓は出さず、話しかける相手の頭上に「！ 相談はこちら」の目印を出す |
| 会話 | 画面の下に会話の窓を1つだけ出す。クリーム色のセリフの枠、大きな顔の絵と名札、いまの一言（1〜2文）。その下に選択肢（選んで進める相談か、返事の選択肢）、いちばん下に自分の言葉で書く小さな欄                                                                                                       |
| 計画 | 旅のしおり（旅程・地図・出典）を右から開く。上に旅の進み具合（祭りの候補 › 旅程の案内 › 確認 › 旅のしおり）。祭りの候補はカードかリストで店内に重ねる                                                                                                                                             |

- 中央はお客さんの目の高さから見た店内。旅人（ペンギン）を歩かせて、スタッフに話しかけたり、店の仕掛けを使ったりできる。旅人の近くにあるものに応じて「E ○○と話す」「E おみくじを引く」などの案内が出る。近くに何もなければ、E は会話の窓を出す
- 操作の説明は、最初に店に入ったときだけ「はじめての方へ」として出す。閉じるか話しかけると消え、その端末で覚えておく。そのあとは「使い方」から、操作の一覧と店の中のようす（近くにあるもの、見つけた隠れひよこの数、店の時計の時刻）を開ける。店の中のようすは、いつも読み上げにも伝える
- 会話の履歴はふだん出さない。お知らせ（会話の記録）で、これまでのやりとりと、スタッフ全員のようすを文字で読める。会話の窓に出ない作業の記録が増えると、印が付く
- 旅のしおりの「旅程」は、日ごとのカード（1日目・2日目…）に予定のアイコンを矢印でつないで流れを見せ、その夜に泊まる地域を添える。その下にくわしい予定と道のりの地図を置く。組み直したら「更新！」の札を貼る
- スマートフォンでは、操作の案内をメニューにまとめる。旅のしおりは画面の上に重ねる
- 見た目は、温かいクリーム色（和紙）、薄い輪郭線、柔らかい影、角丸でそろえる。色・角丸・線・影はトークン（`apps/web/src/index.css` の `@theme`）にまとめ、部品ごとに別の値を書かない

### 会話の窓

- **セリフ**：1〜2文に縮めて出す。くわしい説明・公式サイト・開催日はカードと旅のしおりで見せる。全文は「つづきを読む」と会話の記録で読める（調べた根拠や出典は消さない）
- **選んで進める相談**：店に入って最初に話しかけると、上から順に答える聞き取り（だれと › 日程 › 出発地 › 行き先 › 楽しみ › 食べたいもの › 旅のペース › 予算 › ひとこと › 確認）を出す。手で文章を書かなくても相談を始められる
- **返事の選択肢**：返答のあとは、相談の進み具合に合わせて「祭りの候補を見る」「旅程を見る」「この旅程で決める」「もっとゆっくり回りたい」「条件を選び直す」「旅のしおりを開く」などを出す。最後はいつも「その他（自由に書く）」。「この旅程で決める」は押し間違えで再確認が始まらないよう、「決定して、開催を確かめる」「もどる」でもう一度確かめてから送る
- **会話の窓の大きさ**：自由に書く欄は、書き始めたら（下書きがあるときだけ）広げ、焦点が移るだけでは大きさを変えない。焦点が外れた瞬間に欄が縮むと、窓の中のボタンの位置がずれ、押したボタンが押されなかったり別のボタンが押されたりするため
- **自分の言葉で書く欄**：ふだんは1行の小さな欄で、書いている間だけ広げる。別のチャット欄は出さない。選んで進める相談の間は出さない
- **待つ間**：顔の絵が考える仕草をし、「ちょっと調べてみますね」のような短いひとことを出す

### 選んで進める相談の項目

上から順に1つずつ答える一本道です。上の段に「＜ 段階の名前 3 / 10 ＞」と進み具合の帯を出し、＜ ＞ で答えた段階までを行き来できます（まだ答えていない段階より先へは進めない）。1つだけ選ぶ項目は、選ぶとすぐ次の段階へ進みます。いくつでも選べる項目・人数・期間・自由記述は「決定」で進みます。答えなかった項目は送らず、推測で埋めません。

| 段階         | 答え方                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| だれと       | ひとりで（1人）・家族で・友人と・恋人と（2人）・おまかせ・その他。家族は大人（中学生以上）・子ども（小学生）・幼児・シニアを別々に、友人は人数（2〜20人）を ＋/− で入れる。家族には大人かシニアを1人は残す。送る文では条件の形（`PartySchema`）に合わせ、シニアは大人の内数、幼児は子どもの内数として書く                                                                                                                   |
| 日程         | 今週末・来週末・今月中・来月・日付を指定・日にちは未定。日付を指定は、すぐ期間のカレンダーを開き、行きと帰りの日を選ぶ（同じ日なら日帰り、6泊まで）。ほかは続けて日帰り・1泊・2泊・3泊以上を選び、そこまで選んで答えになる（泊数を伝えるため）                                                                                                                                                                              |
| 出発地       | 最寄りの駅を入れる。打ちはじめたら駅の一覧（[出発の駅の一覧](../stations.md)）から候補を出す。一覧にない駅名もそのまま決められる。欄の下に、一覧の出典（国土数値情報（鉄道データ）を加工して作成。公式のページへのリンク）を小さく出す。その下で、想定している交通手段（車・新幹線・在来線・バス・船・飛行機・レンタカー・徒歩。いくつでも、選ばなければおまかせ。`TRANSPORT_MODES`）を選べる。交通手段だけでは先へ進めない |
| 行き先       | 地方（北海道・東北・関東・中部・近畿・中国・四国・九州・沖縄。いくつでも）・おまかせ・その他。地方を選ぶと、その中の都道府県でもしぼれる。日帰り（日帰りを選んだか、行きと帰りが同じ日）のときだけ、出発の駅からの片道の所要時間（1時間・2時間・3時間以内。押し直すと外す）でもしぼれ、送る文では `maxTravelMinutes` に当たる言葉で書く。泊まりの旅に変えたら、所要時間は送らない                                           |
| 楽しみ       | 温泉・観光と街歩き・写真・体験・自然・歴史・買い物（いくつでも）・おまかせ・その他                                                                                                                                                                                                                                                                                                                                          |
| 食べたいもの | 海鮮・肉料理・野菜中心・麺類・郷土料理・ご当地とB級グルメ・和食・甘味とカフェ・屋台・地酒と地ビール（いくつでも、`FOOD_WISHES`）・おまかせ・その他。下に、食事で気をつけたいこと（ベジタリアン・ヴィーガン・ハラール・食物アレルギー・生ものが苦手。いくつでも、選ばなくてもよい。`DIETARY_NEEDS`）                                                                                                                         |
| 旅のペース   | ゆっくり・ふつう・たっぷり・おまかせ・その他                                                                                                                                                                                                                                                                                                                                                                                |
| 予算         | はじめに金額の数え方（1人あたり・全員で。選ばなければ1人あたり）を選び、目安（〜1万円・〜3万円・〜5万円・それ以上）・おまかせ、または金額（円）を直接入れる。送る文と確認の一覧では、金額に数え方を必ず添える（例：「〜3万円（1人あたり）」「75,000円（全員で）」）                                                                                                                                                         |
| ひとこと     | ほかに伝えたいことを自由に書く。書かなくても進める                                                                                                                                                                                                                                                                                                                                                                          |
| 確認         | 答えの一覧。各行の「直す」でその段階へ戻り、答えると確認へ戻る。「この内容で相談する」で送る                                                                                                                                                                                                                                                                                                                                |

- 自由記述の欄は、「その他」を選んだときと「ひとこと」の段階だけに出す。聞き取りの間は、会話の窓の下の自分の言葉で書く欄を出さない
- 確認の段階で、選んだ内容を1つの発言にまとめて送る（`POST /api/chat` の `message`。サーバーの受け取りは変えない）。接客エージェントは、ほかの発言と同じように条件を読み取る
- 日付の範囲・泊数・人数の合計は、画面のコードで計算して添える（例：今週末（2026-11-07〜2026-11-08）、2026-11-14〜2026-11-16（2泊3日）、家族で（大人3人（うちシニア1人）、子ども1人、計4人））。モデルに計算させない
- キーボードだけで最後まで答えられる。カレンダーは矢印キーで日を動かして Enter で選び、駅の候補は ↑↓ で選んで Enter で決める
- 自分の言葉で送ったら、選んで進める相談はしまう。「条件を選び直す」で、選んだ内容を残したまま開き直せる

| ---------- | -------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| 店の外観   | タイトル、店の外観、入店のボタン | 「小さな町の祭りの旅行代理店」の一言                                               | なし                                               |
| 店         | 旅の案内のカード、日付           | 日付、出発地、旅程の名前、主役の祭りの見どころ、次にすること。読み取れた順に埋まる | `done`、`itinerary.updated`                        |
| 店         | 店内のスタッフ                   | 4人の位置と動き、吹き出し                                                          | `staff.start`、`tool.start`、`tool.end`            |

| 店         | 旅程のパネル「地図」             | 予定の場所のピンと順番の線。会場は大きなピン                                       | `itinerary.updated`、`tool.end`（`search_nearby`） |

| 旅のしおり | 紙面（下の節）                   | 旅程、見どころ、地元の味、作法、注意、出典                                         | `festival.verified` のあとに開く                   |

確度のバッジの色と意味は [データの仕様](data.md#1-出典は必須) にあります。

## 祭りのカード

祭りの候補は、カード表示とリスト表示で切り替えて見られます。選んだ表示はこの端末に覚えておき、次に開いたときもその表示で出します。どれも祭りのデータと候補の項目から出し、その場で文章を作りません。祭りのデータがまだ届いていないときは、候補の項目だけで出します。写真は使わず、祭りの種類ごとに図形で描いた絵（種類の色・山並み・灯り・紋の図柄）を使います。

- **カード表示**：横長のカードに、種類の絵（種類の名前の札つき）、祭りの名前、希望日からのずれ（切手のような札：ご希望の日・1日前など）、場所、日付と時刻、確度のバッジ、ひとこと（見どころ）、目印のタグ、「この祭りにする」「詳細を見る」を並べる
- **リスト表示**：1行に名前・日時・場所・確度と、「この祭りにする」「詳細を見る」をまとめ、多くの候補を一度に見比べられるようにする
- **目印のタグ**：夜のイベント（17時以降に始まる）・参加できる・穴場・屋台あり・子連れで寄れる場所あり。データで分かるものだけを付ける。ご希望の日は札で出すので、カードのタグには重ねない
- **詳細を見る**：おすすめポイント（見どころ最大3つと、条件に合う理由）、ここでしか（祭りの小話を1つ、出典つき）、この祭りの特徴（規模と穴場度を目盛りで、加われるか・屋台・地元の味を短い言葉で）
- **出典**と、情報の訂正・掲載停止の窓口は、カードではいつも見せる。リストでは「詳細を見る」の中に出す
- 開催が確認できていない祭りは「この祭りにする」を押せない。理由（今年の開催がまだ確認できていないこと）を文字で出す
- 候補が2つ以上あれば、エリア（都道府県）・時期（月）・テーマ（祭りの種類）をドロップダウンで絞り込める。選択肢には合う候補の数を添える
- 上に、コンシェルジュのひとこと（例：「○○で、ちょっと珍しいお祭りを見つけたよ！」）を1行で出す。広い画面では、ちょうちん・山並み・鳥居・花火の帯を飾りとして添える（読み上げず、動かさない）
- 「この祭りにする」を押すと、旅程を組み始める

## 旅のこだわり

条件は会話でも伝えられますが、よく使うものはタップで選べるようにします。4項目に絞り、どれも1つを選ぶ切り替えです（選択肢は [旅程の仕様](itinerary.md#こだわりの効果)）。選び直すと、旅程係だけが動いて旅程を組み直します。

- こだわりは、上の丸いボタン「旅のこだわり」から開く小さな切り替えにする。別の画面にしない
- 会話で「子どもと」と言えば「子連れ」が選ばれる。タップと会話のどちらで伝えても同じ結果になる（`done` の `preferences` で画面に返す）
- 日付・出発地・食べたいものなどの旅の好みは、会話の窓の「選んで進める相談」（上の節）で聞く
- 切り替えた直後は、変わった予定だけを色で示す

## 待ち時間の見せ方

エージェントが考えている時間も、楽しめる時間にします。スタッフが持ち場へ動いて作業するようすを見せ、待っている間は豆知識係が祭りの話をします。小話は、利用者が選ばなかった祭りにも光を当てます。

- スタッフの動きと吹き出しは、フックのイベントから決まる。Claude には書かせない
- 候補が出ると祭りのカードが開き、旅程が変わると旅程のパネルに「更新！」の札が貼られる
- 再確認が通ると「旅のしおり完成」の演出が入る

### スタッフどうしの頼みと受け渡し

スタッフはそれぞれ別のエージェントとして動きます。だれがだれに何を頼み、何を受け取ったかを、店内の動きと文字で見せます。サーバーが送るのは「だれが作業を始めたか」（`staff.start`）と「ツールを使い終えたか」（`tool.end`）だけなので、画面はその並びから決まった決まりで頼みと受け渡しを組み立て、ストアの `relay` に持ちます（`apps/web/src/state/relay.ts`）。

| 契機                                            | 頼みと受け渡し                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------- |
| `staff.start`                                   | コンシェルジュがその人に頼む。相手の方を向いて指し、「〇〇さん、…をお願い！」 |
| `tool.end`（うまくいったとき）                  | そのスタッフが結果を持つ。コンシェルジュの頼みの吹き出しを下ろす              |
| 旅程係の `staff.start`                          | ほかのスタッフが持っている結果（寄り道の候補など）を旅程係へ渡す              |
| ほかのスタッフの `staff.start`・`message.delta` | 持っている結果をコンシェルジュへ渡す。コンシェルジュは渡した人の方を向く      |
| `itinerary.updated`                             | 旅程係が旅程をカウンターのコンシェルジュへ運ぶ                                |
| 返答の終わり（`done`・接続が閉じた）            | 残りの結果をコンシェルジュへ渡し、頼みと向きを片付ける                        |

- 頼みの吹き出しと受け渡しの文は、作業の種類から画面の辞書の決まった型で作る。モデルの文章は使わない
- 受け渡しは、渡す人の頭の上から受け取る人の頭の上へ、手紙が山なりに渡る動きで見せる。2D の見取り図では、いちばん新しい頼みか受け渡しを、渡す人から受け取る人への点線で出す
- 作業中のスタッフの頭の上には、いまのようすの札を出す：向かっている・頼んでいる・調べている（祭りと寄り道の検索）・確かめている（アクセス・天気・開催の再確認）・まとめている（旅程の書き込み、ツールを使い終えて持ち場にいる間）・届けている（書類を運ぶ）
- 同じことは文字でも読める。返答を待つ間は「店内のようす」の窓に、いまのようすの札と、この発言の頼みと受け渡しの新しい4件を出す。会話の記録には、これまでの頼みと受け渡しをすべて（新しい40件まで）出す
- 動きを減らす設定のときは 3D を出さず、2D の見取り図と文字で出す。点線や札は出てくる動きを付けない

### 豆知識係

- 返事を待つ間、「コンシェルジュの豆知識」の窓を出し、3D ではコンシェルジュの頭の上にも吹き出しで出す。広い画面でしおりを開いていないときは、店内のようすと縦に並べて右に置き、会話の窓を左に寄せる。それ以外は会話の窓の上に置く
- 豆知識とクイズは同じ1つの窓に出す。クイズが出ている間はクイズを、閉じると豆知識を出す
- 中身は祭りのデータの小話（`trivia`）・見どころ・作法を、種類が続かないよう交互に並べ、出典を添える。その場で Claude に作らせないので、待ち時間が増えず、誤りも入らない
- 候補が出る前は、読み込んだ祭りの全体（`GET /api/festivals`）から話す。候補が出たあとは、候補と主役の祭りの話に切り替える
- 話は吹き出しと、祭りの種類の絵葉書（このアプリで描いた色と紋）で見せる。出典は「くわしく見る」で開く
- 7秒ごとに次の話へ移る。「前の話」「次の話」「止める／続ける」ができ、マウスを乗せている間・くわしく見ている間・動きを減らす設定のときは自動では進まない
- だれが何をしているかと、スタッフごとの経過時間、全体の経過時間は「店内のようす」の窓に出す。20秒を過ぎたら、時間がかかることを伝える
- 「この祭りも候補に」を押すと、その祭りを候補に入れてほしいという一文が返事の欄に入る（送るのは利用者）

### 祭りのクイズ

- 10秒以上待ちそうなときだけ、2択のクイズを1問出す（例：「この祭りの屋台の名物はどっち？」）
- 問題と選択肢は祭りのデータの項目から組み立てる。正解すると、画面の中のしおりの表紙にスタンプの印が1つ増える
- 答えなくても進む。閉じると同じ窓が豆知識に戻り、結果が出たら窓ごと消える

### 手ざわりと音

- スタッフの吹き出しは短く、キャラクターらしい口調にする
- 効果音は太鼓、拍子木、はんこの3種類だけ。音は最初は切っておき、ボタンで鳴らせるようにする
- BGM は和太鼓の曲を1つだけ流す。効果音と同じボタンに従い、音がオンの間だけ小さめの音量で繰り返す（素材と出典は `assets/audio/README.md`）
- 演出は1回 0.5〜1.5 秒に収め、何度見ても邪魔にならない長さにする
- 動きを減らす設定（`prefers-reduced-motion`）のときは、演出を控えめにし、2D の表示を主にする

## 旅のしおり

しおりは2つあります。店の画面から開く画面の中のしおりは1枚の紙面で（表紙・今日の主役・1日の流れ・地図・地元の味・はじめての方へ・雨の日の案・出典。泊まりの旅は日ごとに見出しを付ける）、ブラウザで印刷でき、共有の URL とそれを写すボタンを出します。共有の URL で開くしおりは、サーバーが作る A4 縦の紙面で、画面で開く HTML と、印刷や保存に使う PDF を同じテンプレートから作ります（HTML の「PDF で保存・印刷する」から開く）。以下はこの A4 のしおりの中身です。半日のお出かけは4ページほど、泊まりの旅は日ごとにページが増えます（6泊7日まで）。表紙の絵と色は祭りの種類と季節で決まり、スタッフと旅人の絵が各ページに出ます。中身・ページの並び・素材・PDF の作り方は [旅のしおりの仕様](shiori.md) にあります。

1. **表紙**：旅の名前、旅の長さ、日にち、同行者、主役の祭り、天気、公式の情報で開催を確かめた印
2. **旅の全体**（泊まりの旅）：旅のかたち（どこを回るか）の図、日ごとの予定と泊まる地域
3. **祭りの紹介**：祭りの名前、日時、場所、規模、見どころ3つまで、小話、その土地の味、アクセス
4. **日ごとの流れ**（祭りの日とそうでない日で見た目を変える）：時刻つきの予定と、それぞれの「ここに入れた理由」、移動の目安、泊まる地域、雨の日の案
5. **はじめての方へ**：ルールとマナー、服装、持ち物、危険度、見学のみか加われるか、写真を撮ってよいか。分からない項目は「分からない」と書く。交通規制・駐車場・荒天のときの注意もここにまとめる。日本語と英語の両方で出す。行く人の不安と、「しきたりを守ってほしい」という主催者の不安の両方に応えるページなので、祭りの側のお願い（立ち入ってはいけない場所、撮ってはいけない場面など）をはっきり書く
6. **持ち物のチェックリスト**：祭りのデータの持ち物と服装、旅程のメモ、いつもの持ち物
7. **スタンプ帳とメモ**
8. **出典**：使った情報源の URL と確認した日。「当日は公式の情報で最終確認を」の一文

## 使いやすさ

- 祭りのデータとモデルの文章は、必ず文字列として表示する。HTML として埋め込まない
- 3D に出す情報（スタッフの作業、吹き出し、進み具合）は、すべて文字でも読める
- 屋外のスマートフォンでも読める、文字の濃さと大きさにする
- 地図は Leaflet と OpenStreetMap のタイルを使い、帰属の表示を必ず出す
- 日本語と英語を切り替えられる。文言は小さな辞書のファイルで持つ

## 3D の店内

3D の店内は、状態の見た目の層です（[ADR 0003](../adr/0003-3d-as-a-view-layer.md)）。モデルとモーションはすべて新しく作り、既存のゲームやキャラクターに似せません。

| 項目           | 仕様                                                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 雰囲気         | 丸みのあるローポリ、やわらかい色、トゥーン調                                                                                                                        |
| 店の外観       | 小さな商店街の一角。のれん、提灯、祭りのポスター。入店のときにカメラが寄る                                                                                          |
| 店内           | 1部屋。カウンター、資料棚、地図の壁、時刻表、祭りのポスター                                                                                                         |
| 旅人           | 利用者が動かすペンギン。WASD・矢印・ゲームパッドの左スティックと十字キー・タップで歩く。タップした場所へは、10cm の升目の上で道を探して歩く。柵や家具は通り抜けない |
| 遊び           | 呼び鈴・おみくじ・ガチャ・だるま・猫など12の仕掛け、座れる席、隠れひよこ3羽、本当の時刻を指す時計。入口の近くでは入口の壁を透かす                                   |
| スタッフ       | 4人。共通のリグを使い、法被の色と小物（眼鏡、地図、時刻表、はんこ）で見分ける                                                                                       |
| モーション     | スタッフは、待機、歩く、作業（めくる・指さす・見上げる）、うなずく、話す、はんこを押す。各 2〜3 秒のループ                                                          |
| 動きの制御     | スタッフはストアの状態で切り替わる（待機 → 持ち場へ歩く → 作業 → 戻る）。持ち場の位置は固定                                                                         |
| 吹き出し       | 3D の上に HTML を重ねて出す。文章はフックの決まった型から作る。作業中のスタッフには、いまのようすの札を付ける                                                       |
| 頼みと受け渡し | コンシェルジュは頼んだ相手・結果を渡した相手の方を向く。受け渡しは手紙が山なりに渡る（[スタッフどうしの頼みと受け渡し](#スタッフどうしの頼みと受け渡し)）           |
| カメラ         | 客の目線の高さから、旅人に合わせて横と奥行きに動く。入店のときに1回だけ寄り、しおりの完成のときはカウンターへ寄る                                                   |
| 照明           | 焼き込みの照明と、提灯の弱い光。リアルタイムの影は使わない                                                                                                          |
| 性能           | 60fps を目標にする。店内全体で5万三角形以下、GLB の合計 5MB 以下、テクスチャは1辺 1024px 以下                                                                       |

モデルは Blender で作り、GLB で書き出して React Three Fiber で読み込みます。作るためのスクリプトは `assets/3d/` に置きます。

読み込みの待ちは、次のように短くし、待っていることが分かるようにします。

- 店の外観を開いたらすぐ、3D のコードと同時に、店内と外観のモデルを取り始める
- 描けるまでは、取ったモデルの割合を「店の明かりを灯しています」で出し、取り終えたら（GPU に送る間）「店を整えています」にする
- 外観が描けたら、店内のコードと、スタッフ・旅人・モーションのモデルを先に読んでおく。入店のときにまだ取れていなければ、同じ表示を出す
- ビルドで圧縮済みのファイル（`.br`・`.gz`）を作り、接客サーバーはブラウザが受け取れる方を返す
