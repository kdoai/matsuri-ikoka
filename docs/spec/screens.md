# 画面の仕様

## 画面の一覧

画面は4つです。相談から旅程の修正までは、店の画面1枚の中で済ませます。

1. **店の外観**：タイトルと「入店する」ボタン。すぐに相談を始められる入り口
2. **店の画面**：画面いっぱいの 3D の店内。表示を「探索」「会話」「計画」の3つに分け、そのとき要るものだけを重ねる。ゲームの画面の中で話しかけ、選択肢を選んで相談を進める
3. **祭りの候補**：店内に重ねて出す祭りのカード。選ぶと消えて、旅程のパネルに旅程が出る
4. **旅のしおり**：確定したあとに全画面で開く画面の中のしおり（1枚の紙面、ブラウザで印刷できる）。共有の URL（`/shiori/<旅程の ID>`）では、サーバーが作る A4 のしおり（HTML と PDF、下の「旅のしおり」）を開ける

### 店の画面の並び

店の画面はいつも店内が主役です。表示を3つの場面に分け、探索するときは探索、話すときは会話、旅を計画するときは詳細だけに集中できるようにします。

| 場面 | 出すもの                                                                                                                                                                                                                                                                                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 探索 | 左上にロゴと日付の小さな札（旅の日と出発の駅）。右上に丸いボタン（お知らせ、旅のこだわり、設定、使い方、ログインと自分の旅）。右下に小さな操作の案内（Ⓧ 旅程詳細・Ⓨ 地図・Ⓜ メニュー）。下に小さな「話しかける」のボタン。会話の窓は出さず、話しかける相手の頭上に「！ 相談はこちら」の目印を出す |
| 会話 | 画面の下に会話の窓を1つだけ出す。クリーム色のセリフの枠、大きな顔の絵と名札、いまの一言（1〜2文）。その下に選択肢（選んで進める相談か、返事の選択肢）、いちばん下に自分の言葉で書く小さな欄                                                                                                       |
| 計画 | 旅のしおり（旅程・地図・出典）を右から開く。上に旅の進み具合（祭りの候補 › 旅程の案内 › 確認 › 旅のしおり）。祭りの候補は絵葉書のカードで店内に重ねる                                                                                                                                             |

- 中央はお客さんの目の高さから見た店内。旅人（ペンギン）を歩かせて、スタッフに話しかけたり、店の仕掛けを使ったりできる。旅人の近くにあるものに応じて「E ○○と話す」「E おみくじを引く」などの案内が出る。近くに何もなければ、E は会話の窓を出す
- 操作の説明は、最初に店に入ったときだけ「はじめての方へ」として出す。閉じるか話しかけると消え、その端末で覚えておく。そのあとは「使い方」から、操作の一覧と店の中のようす（近くにあるもの、見つけた隠れひよこの数、店の時計の時刻）を開ける。店の中のようすは、いつも読み上げにも伝える
- 会話の履歴はふだん出さない。お知らせ（会話の記録）で、これまでのやりとりと、スタッフ全員のようすを文字で読める。会話の窓に出ない作業の記録が増えると、印が付く
- 旅のしおりの「旅程」は、日ごとのカード（1日目・2日目…）に予定のアイコンを矢印でつないで流れを見せ、その夜に泊まる地域を添える。その下にくわしい予定と道のりの地図を置く。組み直したら「更新！」の札を貼る
- スマートフォンでは、操作の案内をメニューにまとめる。旅のしおりは画面の上に重ねる
- 見た目は、温かいクリーム色（和紙）、薄い輪郭線、柔らかい影、角丸でそろえる。色・角丸・線・影はトークン（`apps/web/src/index.css` の `@theme`）にまとめ、部品ごとに別の値を書かない

### 会話の窓

- **セリフ**：1〜2文に縮めて出す。くわしい説明・公式サイト・開催日はカードと旅のしおりで見せる。全文は「つづきを読む」と会話の記録で読める（調べた根拠や出典は消さない）
- **選んで進める相談**：店に入って最初に話しかけると、段階のタブ（誰と行く？ › いつ？ › どこへ？ › 日帰り・泊まり › 楽しみ › 食べたいもの › 旅のスタイル › 確認）と、大きなボタンの選択肢を出す。手で文章を書かなくても相談を始められる
- **返事の選択肢**：返答のあとは、相談の進み具合に合わせて「祭りの候補を見る」「旅程を見る」「この旅程で決める」「もっとゆっくり回りたい」「条件を選び直す」「旅のしおりを開く」などを出す。最後はいつも「その他（自由に書く）」
- **自分の言葉で書く欄**：ふだんは1行の小さな欄で、書いている間だけ広げる。別のチャット欄は出さない
- **待つ間**：顔の絵が考える仕草をし、「ちょっと調べてみますね」のような短いひとことを出す

### 選んで進める相談の項目

どの項目にも「おまかせ」と「その他」（選ぶと自由記述の欄が開く）があります。答えなかった項目は送らず、推測で埋めません。

| 項目                       | 選択肢                                                           |
| -------------------------- | ---------------------------------------------------------------- |
| 誰と                       | ひとりで・家族で・友人と・恋人と                                 |
| いつ                       | 今週末・来週末・今月中・来月・日付を選ぶ                         |
| 出発する駅                 | 駅名を書く                                                       |
| 行きたいところ             | 近場で・少し遠くへ                                               |
| 日帰り・泊まり             | 日帰り・1泊・2泊・3泊以上                                        |
| 祭りのほかに楽しみたいこと | 温泉・観光と街歩き・写真・体験・自然・歴史・買い物（いくつでも） |
| 食べたいもの               | 海鮮・郷土料理・甘味・屋台・地酒（いくつでも）                   |
| 旅のペース                 | ゆっくり・ふつう・たっぷり                                       |
| 予算の感じ                 | おさえめ・ふつう・ちょっと贅沢                                   |

- 確認の段階で、選んだ内容を1つの発言にまとめて送る（`POST /api/chat` の `message`。サーバーの受け取りは変えない）。接客エージェントは、ほかの発言と同じように条件を読み取る
- 今週末・来週末・今月中・来月は、画面のコードで日本の日付にして添える（例：今週末（2026-11-07〜2026-11-08））。モデルに日付を計算させない
- 自分の言葉で送ったら、選んで進める相談はしまう。「条件を選び直す」で、選んだ内容を残したまま開き直せる

| 店         | 旅の案内のカード、日付           | 日付、出発地、旅程の名前、主役の祭りの見どころ、次にすること。読み取れた順に埋まる | `done`、`itinerary.updated`                        |

確度のバッジの色と意味は [データの仕様](data.md#1-出典は必須) にあります。

## 祭りのカード

祭りの候補は、絵葉書のようなカードにします。どれも祭りのデータと候補の項目から出し、その場で文章を作りません。祭りのデータがまだ届いていないときは、候補の項目だけで出します。写真は使わず、祭りの種類の色と紋の図柄で絵葉書らしく見せます。

- **絵の面**：祭りの種類（灯籠・山車・踊りなど）の色と紋、祭りの名前、場所、希望日からのずれ（切手のような札）
- **表**：日付と時刻、確度のバッジ、ひとこと（見どころ）、目印のタグ。未確認なら、そのことをはっきり書く
- **目印のタグ**：ご希望の日・夜のイベント（17時以降に始まる）・参加できる・穴場・屋台あり・子連れで寄れる場所あり。データで分かるものだけを付ける
- **詳細を見る**：おすすめポイント（見どころ最大3つと、条件に合う理由）、ここでしか（祭りの小話を1つ、出典つき）、この祭りの特徴（規模と穴場度を目盛りで、加われるか・屋台・地元の味を短い言葉で）
- **出典**と、情報の訂正・掲載停止の窓口はいつも見せる
- 候補が2つ以上あれば、エリア（都道府県）・時期（月）・テーマ（祭りの種類）で絞り込める
- カードの上に、コンシェルジュのひとこと（例：「○○で、ちょっと珍しいお祭りを見つけたよ！」）を1行で出す
- 「この祭りにする」を押すと、旅程を組み始める

## 旅のこだわり

条件は会話でも伝えられますが、よく使うものはタップで選べるようにします。4項目に絞り、どれも1つを選ぶ切り替えです（選択肢は [旅程の仕様](itinerary.md#こだわりの効果)）。選び直すと、旅程係だけが動いて旅程を組み直します。

- こだわりは、上の丸いボタン「旅のこだわり」から開く小さな切り替えにする。別の画面にしない
- 会話で「子どもと」と言えば「子連れ」が選ばれる。タップと会話のどちらで伝えても同じ結果になる（`done` の `preferences` で画面に返す）
- 日付・出発地・食べたいものなどの旅の好みは、会話の窓の「選んで進める相談」（上の節）で聞く
- 切り替えた直後は、変わった予定だけを色で示す

## 待ち時間の見せ方

エージェントが考えている時間も、楽しめる時間にします。スタッフが持ち場へ動いて作業するようすを見せ、待っている間は豆知識係が祭りの話をします。小話は、利用者が選ばなかった祭りにも光を当てます。

- スタッフの動きと吹き出しは、フックのイベントから決まる。Claude には書かせない
- 候補が出ると祭りのカードが開き、旅程が変わると旅程のパネルに「更新！」の札が貼られる
- 再確認が通ると「旅のしおり完成」の演出が入る

### 豆知識係

- 返事を待つ間、会話の窓の上に「待ち時間の豆知識」を出し、3D ではコンシェルジュの頭の上にも吹き出しで出す
- 中身は祭りのデータの小話（`trivia`）・見どころ・作法を、種類が続かないよう交互に並べ、出典を添える。その場で Claude に作らせないので、待ち時間が増えず、誤りも入らない
- 候補が出る前は、読み込んだ祭りの全体（`GET /api/festivals`）から話す。候補が出たあとは、候補と主役の祭りの話に切り替える
- 7秒ごとに次の話へ移る。「次の話」「止める／続ける」ができ、マウスを乗せている間と、動きを減らす設定のときは自動では進まない
- だれが何をしているかと、スタッフごとの経過時間、全体の経過時間も出す。20秒を過ぎたら、時間がかかることを伝える
- 「この祭りも候補に」を押すと、その祭りを候補に入れてほしいという一文が返事の欄に入る（送るのは利用者）

### 祭りのクイズ

- 10秒以上待ちそうなときだけ、2択のクイズを1問出す（例：「この祭りの屋台の名物はどっち？」）
- 問題と選択肢は祭りのデータの項目から組み立てる。正解すると、画面の中のしおりの表紙にスタンプの印が1つ増える
- 答えなくても進む。結果が出たら自動で閉じる

### 手ざわりと音

- スタッフの吹き出しは短く、キャラクターらしい口調にする
- 効果音は太鼓、拍子木、はんこの3種類だけ。音は最初は切っておき、ボタンで鳴らせるようにする
- 演出は1回 0.5〜1.5 秒に収め、何度見ても邪魔にならない長さにする
- 動きを減らす設定（`prefers-reduced-motion`）のときは、演出を控えめにし、2D の表示を主にする

## 旅のしおり

しおりは2つあります。店の画面から開く画面の中のしおりは1枚の紙面で（表紙・今日の主役・1日の流れ・地図・地元の味・はじめての方へ・雨の日の案・出典。泊まりの旅は日ごとに見出しを付ける）、ブラウザで印刷でき、共有の URL とそれを写すボタンを出します。共有の URL で開くしおりは、サーバーが作る A4 縦の紙面で、画面で開く HTML と、印刷や保存に使う PDF を同じテンプレートから作ります（HTML の「PDF で保存・印刷する」から開く）。以下はこの A4 のしおりの中身です。半日のお出かけは4ページほど、泊まりの旅は日ごとにページが増えます（6泊7日まで）。表紙の絵と色は祭りの種類と季節で決まり、スタッフと旅人の絵が各ページに出ます。中身・ページの並び・素材・PDF の作り方は [旅のしおりの仕様](shiori.md) にあります。

1. **表紙**：旅の名前、旅の長さ、日にち、同行者、主役の祭り、天気、公式の情報で開催を確かめた印
2. **旅の全体**（泊まりの旅）：旅のかたち（どこを回るか）の図、日ごとの予定と泊まる地域
3. **祭りの紹介**：祭りの名前、日時、場所、規模、見どころ3つまで、小話、その土地の味、アクセス
4. **日ごとの流れ**（祭りの日とそうでない日で見た目を変える）：時刻つきの予定と、それぞれの「ここに入れた理由」、移動の目安、泊まる地域、雨の日の案
5. **はじめての方へ**：ルールとマナー、服装、持ち物、危険度、見学のみか加われるか、写真を撮ってよいか。分からない項目は「分からない」と書く。交通規制・駐車場・荒天のときの注意もここにまとめる。日本語と英語の両方で出す。行く人の不安と、「しきたりを守ってほしい」という主催者の不安の両方に応えるページなので、祭りの側のお願い（立ち入ってはいけない場所、撮ってはいけない場面など）をはっきり書く
6. **持ち物のチェックリスト**：祭りのデータの持ち物と服装、旅程のメモ、いつもの持ち物
7. **スタンプ帳とメモ**
8. **出典**：使った情報源の URL と確認した日。「当日は公式の情報で最終確認を」の一文

## 使いやすさ

- 祭りのデータとモデルの文章は、必ず文字列として表示する。HTML として埋め込まない
- 3D に出す情報（スタッフの作業、吹き出し、進み具合）は、すべて文字でも読める
- 屋外のスマートフォンでも読める、文字の濃さと大きさにする
- 地図は Leaflet と OpenStreetMap のタイルを使い、帰属の表示を必ず出す
- 日本語と英語を切り替えられる。文言は小さな辞書のファイルで持つ

## 3D の店内

3D の店内は、状態の見た目の層です（[ADR 0003](../adr/0003-3d-as-a-view-layer.md)）。モデルとモーションはすべて新しく作り、既存のゲームやキャラクターに似せません。

| 項目       | 仕様                                                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 雰囲気     | 丸みのあるローポリ、やわらかい色、トゥーン調                                                                                                                        |
| 店の外観   | 小さな商店街の一角。のれん、提灯、祭りのポスター。入店のときにカメラが寄る                                                                                          |
| 店内       | 1部屋。カウンター、資料棚、地図の壁、時刻表、祭りのポスター                                                                                                         |
| 旅人       | 利用者が動かすペンギン。WASD・矢印・ゲームパッドの左スティックと十字キー・タップで歩く。タップした場所へは、10cm の升目の上で道を探して歩く。柵や家具は通り抜けない |
| 遊び       | 呼び鈴・おみくじ・ガチャ・だるま・猫など12の仕掛け、座れる席、隠れひよこ3羽、本当の時刻を指す時計。入口の近くでは入口の壁を透かす                                   |
| スタッフ   | 4人。共通のリグを使い、法被の色と小物（眼鏡、地図、時刻表、はんこ）で見分ける                                                                                       |
| モーション | スタッフは、待機、歩く、作業（めくる・指さす・見上げる）、うなずく、話す、はんこを押す。各 2〜3 秒のループ                                                          |
| 動きの制御 | スタッフはストアの状態で切り替わる（待機 → 持ち場へ歩く → 作業 → 戻る）。持ち場の位置は固定                                                                         |
| 吹き出し   | 3D の上に HTML を重ねて出す。文章はフックの決まった型から作る                                                                                                       |
| カメラ     | 客の目線の高さから、旅人に合わせて横と奥行きに動く。入店のときに1回だけ寄り、しおりの完成のときはカウンターへ寄る                                                   |
| 照明       | 焼き込みの照明と、提灯の弱い光。リアルタイムの影は使わない                                                                                                          |
| 性能       | 60fps を目標にする。店内全体で5万三角形以下、GLB の合計 5MB 以下、テクスチャは1辺 1024px 以下                                                                       |

モデルは Blender で作り、GLB で書き出して React Three Fiber で読み込みます。作るためのスクリプトは `assets/3d/` に置きます。
