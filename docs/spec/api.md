# API と SSE イベントの仕様

ログインと自分の旅の API（`/api/auth/config`・`/api/trips`・`/api/me/trips`）は [ログインと保存の仕様](account.md#api) にあります。

- 型はどれも `packages/schema`（`api.ts`）にある
- 合言葉（`ACCESS_PASSCODE`）を設定しているときは、`/api/*` にヘッダー `x-access-passcode` が要る。しおり・死活監視・内部の入口には要らない
- 掲載停止の祭りは、`/api/festivals` の一覧に含めず、`/api/festivals/:id` でも 404 にする
- 相談を始める回数（`POST /api/session`）は、IP ごとに1日の上限がある（`DAILY_SESSION_LIMIT_PER_IP`）。超えたら 429（`rate_limited`）
- `GET /api/itinerary/:id` を ID トークンを付けて読んだ応答には、`Cache-Control: private, no-store` を付ける（持ち主自身の旅程がブラウザや途中のキャッシュに残らないようにする）
- 本番では、同じオリジンから画面（`apps/web` のビルド）も配る

### 経路と認可の決まり

すべての経路に、次の4つの決まりのどれかを宣言します。経路は宣言しないと足せません（`apps/server/src/routes/policy.ts`）。宣言のない経路があるとサーバーは起動せず、テストとデプロイの前の確かめで見つかります。

### 内部の入口

定期実行と Webhook のための入口は `/internal/…` に置き、合言葉やログインとは別の検証を通します。検証の設定は省略でき、なければその入口だけが断り、サーバーは起動して相談はそのまま動きます。署名の鍵が空（`whsec_` だけなど）のときは、設定がないものとして扱います。

| 検証        | 呼び出し元                  | 確かめること                                                                                                                                                         | 設定                                                   |
| ----------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `oidc`      | 定期実行（Cloud Scheduler） | `Authorization: Bearer` の Google の OIDC トークンの署名・期限・宛先（audience）と、決めたサービスアカウントのメールアドレス                                         | `INTERNAL_OIDC_AUDIENCE`・`INTERNAL_OIDC_CALLER_EMAIL` |
| `signature` | Managed Agents の Webhook   | `webhook-id`・`webhook-timestamp`・`webhook-signature`（Standard Webhooks の形）。`{id}.{timestamp}.{本文}` の HMAC-SHA256 が合うこと、時刻のずれが5分以内であること | `ANTHROPIC_WEBHOOK_SIGNING_KEY`                        |

見回りの入口は、検証を通っても、見回りを動かしていない環境（mock、または `PATROL_ANTHROPIC_API_KEY` がないとき）では 404 で断ります（[旅の見回り](operations.md#旅の見回り)）。

### 断るときの応答

SSE を始める前に断るときと、JSON を返す API が失敗したときは、HTTP の状態コードと `ApiErrorSchema` の本文（`error` イベントの data と同じ `{ code, message, retryable }`）で返します。

| 状態 | `code`                 | いつ                                                                                                                                                                             |
| ---- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400  | `bad_request`          | 本文の形が正しくない                                                                                                                                                             |
| 401  | `unauthorized`         | 合言葉が違う。ログインが要る API で、ID トークンがない・確かめられない。内部の入口で、呼び出し元を確かめられない                                                                 |
| 404  | `bad_request`          | 相談・旅程・祭りが見つからない。相談や旅程がほかの人のもの（ないときと同じ応答で、あるかどうかを見せない）。ログインを用意していないのに旅の API を呼んだ                        |
| 409  | `bad_request`          | 同じ相談の前の返事を作っている途中（retryable）。旅程がまだないのに旅を残そうとした                                                                                              |
| 413  | `bad_request`          | 本文が大きすぎる                                                                                                                                                                 |
| 429  | `rate_limited`         | 1日の相談の回数の上限（全体、または利用者ごと。ログインしていなければ IP ごと）。ガイドの1日の回数と費用の上限（利用者ごと、旅ごと）。1日に相談を始められる回数の上限（IP ごと） |
| 503  | `upstream_unavailable` | 同時に返事を作れる数を超えた。全体、または利用者ごと（ログインしていなければ IP ごと）（retryable）                                                                              |

### POST /api/festivals/search

祭りから探す相談の検索（[祭りから探す](festival-search.md)）。条件に合う祭りを最大6件、JSON で返します。型は `packages/schema` の `festivalSearch.ts` にあります。

- 本文は `sessionId`・`kinds`・`season`・`prefectures`・`wish`（省略できる）・`excludeIds`（省略できる）。形が違えば 400、相談が見つからなければ 404
- 検索はコードだけで行うので、1日の相談の回数を使わず、回数の上限（429）でも断りません
- 自由記述をモデルで読むときだけ、回数を1回使い、同時に返事を作る枠を1つ使います。同じ相談の同じ自由記述は読み直しません（「別の祭りを提案してもらう」で回数が増えず、順もずれない）
- 回数の上限・混雑・モデルの失敗・時間切れのときは、断らずに言葉の辞書で読みます。どちらで読んだかは `reading.by` で分かります
- モックモードでも動きます（読むのは言葉の辞書だけ）

### POST /api/festival-trips/preview

祭りから探して決めた祭りを軸に、旅の組み立てを計算して返します（モデルは呼びません）。本文は `AnchorPlanRequestSchema`、応答は `AnchorPlanSchema` です。計算の手順は [祭りから探す](festival-search.md#祭りを固定した旅程) にあります。

- 祭りがない・掲載停止は 404。データにない日、中止や延期の回、過ぎた日は 400（どちらも `bad_request`）
- 相談が見つかれば、選んだ出発地・泊数・ペース・寄りたい場所を、その相談の条件に残す（祭りは固定しない）。ほかの人の相談は見つからないものと同じに扱い、何も残さない
- 祭りの固定は、次の `POST /api/chat` の `anchor` で行う

### POST /api/chat

本文は `ChatRequestSchema` です。

```json
{
  "sessionId": "…",
  "message": "8月16日に行ける祭りはありますか",
  "preferences": {
    "party": "adults",
    "spot": "auto",
    "food": "stalls",
    "move": "train"
  }
}
```

- `message` は前後の空白を除いて1〜1000字
- `preferences` は画面で選んでいるこだわり（[旅程の仕様](itinerary.md#こだわりの効果)）
- `anchor`（任意）は、祭りから探して決めた祭りと行く日（`TripAnchorSchema`）。あれば、祭りを固定して旅程を組む。祭りと日を確かめ（断り方は上の `POST /api/festival-trips/preview` と同じ）、相談の状態に残すので、次の発言からは送らなくてよい。固定を外すのはコンシェルジュ（ほかの祭りに変えたいと言われたとき）か、中止と分かったときで、そのあとに同じ `anchor` を送ると固定し直す
- `search`（任意）は、候補の窓の次の手（ボタン）から送るときの、変えて探し直す条件（`SearchRetrySchema`：`when`・`maxTravelMinutes`・`nights`・`widen` のうち1つ以上）。サーバーは聞き取った条件に書き足し（`widen` も残し、次の探し直しに引き継ぐ）、その発言の `search_festivals` はこの条件を正として使う（[条件の守り方](agents.md#条件の守り方)）
- `locale`（任意）は画面の言語（`ja` か `en`。`LocaleSchema`）。省略すると日本語として扱うので、言語を送らない呼び出しもそのまま通る。`PATCH /api/preferences` と `POST /api/guide/chat` の本文にも同じ項目がある。使い方は下の [画面の言語](#画面の言語)

### 画面の言語

画面は、選んでいる言語を発言ごとに `locale` で送ります。文の種類ごとに、次のように言語を合わせます。

- **コンシェルジュとガイドの返事（`message.delta`）**：`locale` が `en` なら、サーバーは店の記録（ガイドは旅の記録）に「画面の言語：英語」の行を足し、英語で返事を書いてもらう。祭り・駅・店の名前はデータの表記のまま書く。スタッフへの依頼と報告は日本語のまま。記録の再生（mock）は記録した文をそのまま流す
- **吹き出しとくわしい文（`bubble`・`detail`）**：サーバーは日本語で作って送る。画面は、イベントに型で届いた値（作業・ツール・成否・件数・いちばん上の候補の名前・調べ直しの中身）から、画面の辞書（`apps/web/src/i18n/`）で言い直す。日本語の画面ではサーバーの文をそのまま出す
- **エラー（`error` と API の本文）**：種類（`code`）と、送り直せるか（`retryable`）から、画面の辞書の文言を出す。送り直せる `bad_request` は、前の返事を作っている途中に送ったときだけなので、そう伝える。日本語の画面ではサーバーの一文を出す
- **しおりの案内のページ（404・409）**：下の [しおりの案内のページ](#しおりの案内のページ)

祭り・店・宿の名前、候補のカードの中身、旅程の予定の文、しおりの本文、ガイドの知らせの文は、データとモデルが書いた文なので、言い直しません。

### しおりの案内のページ

`GET /shiori/:id` と `GET /shiori/:id.pdf` で、しおりをまだ出せないとき（ない旅程の 404、確定していない旅程の 409）の短いページは、日本語と英語で出します。PDF が混み合っているときの 503 の一文も同じです。

- 言語はクエリの `lang`（`ja` か `en`）を先に見て、なければ `Accept-Language` のいちばん初めの言語で決める。日本語でなければ英語、どちらもなければ日本語
- 店内の画面は、しおりを埋め込むとき（`?embed=1`）に画面の言語を `lang` で添える。画面の言語はブラウザの言語と別に切り替えられるので、画面に合わせる
- 共有された URL を直接開いた人には、その人のブラウザの言語で出す（URL に言語を入れないので、同じ URL を日本語と英語の人で共有できる）
- 言語で中身が変わるので、応答に `Vary: Accept-Language` を付ける

## SSE イベント

1つの発言に、SSE の接続を1本使って返します。

- 各イベントは `event:` に種類、`data:` に JSON を入れる。形は `SseEventSchema`
- 最後に必ず `done` を送って閉じる。相談の状態が `done` の形に合わないときも落とさず、読み取れた条件を空にして送る
- 15秒ごとに空のコメント行を送り、途中で接続が切られないようにする
- 接続が切れても自動で再接続はしない。会話欄に「もう一度送る」ボタンと、返事が最後まで届かなかったことと送り直せることを伝える一文を出す（`done` を受け取らずに閉じたときも同じ）
- `done` が届かないまま閉じたら、画面は `/health` でサーバーが応答するかを確かめる（公開の URL では `/healthz` が外から届かないため）。応答しなければ、上の一文の代わりに「サーバーにつながらない」と出す
- 画面の側でイベントの反映に失敗しても、接続が切れたことにはせず、続きを受け取る
- 閉じたら、接客サーバーはログに `turn_end` を1行残す。終わり方（`done`・`error`・`timeout`・`client_closed`：done の前に利用者の側から切れた）、`error` の `code`、`done` を送れたか（`doneSent`）、送ったイベントの数、所要時間。会話の本文は残さない
- 送る前（`encodeSseEvent`）と受け取ったあと（`decodeSseEvent`）に、どちらもスキーマで検証する

| イベント            | いつ                                       | 主な中身                                                                                                                                                                                   |
| ------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `staff.start`       | スタッフ（サブエージェント）が作業を始めた | スタッフ、作業の種類、吹き出し                                                                                                                                                             |
| `tool.start`        | ツールを呼ぶ前                             | ツールの呼び出し ID、ツール名、スタッフ、吹き出し、くわしい文（あれば）                                                                                                                    |
| `tool.end`          | ツールが終わった                           | 成否、吹き出し、くわしい文（あれば）、件数。`search_festivals` なら候補（最大3件）、`search_nearby` なら地図に打つ場所                                                                     |
| `staff.redo`        | スタッフどうしで調べ直しを頼んだ・受けた   | 頼み（`request`）か受け（`accept`）か、言う人（`from`）、相手（`to`）、足りないもの（`subject`）、吹き出し、くわしい文                                                                     |
| `itinerary.updated` | 旅程が保存された                           | 旅程の全体と、前の版からの差分（追加・変更は予定の ID、削除は ID と名前）                                                                                                                  |
| `festival.verified` | 開催を確かめた                             | 祭りの ID、確かめた日付、場面（`scope`：`candidate` は候補を出す前、`itinerary` は確定前。省略は `itinerary`）、結果（予定どおり・要事前確認・変更・中止・確認できず）、出典、確認した時刻 |
| `message.delta`     | コンシェルジュの返答の続き                 | 返答の ID と文章の続き                                                                                                                                                                     |
| `error`             | 何かがうまくいかなかった                   | 種類、利用者に見せる短い一文、もう一度送れば直るか                                                                                                                                         |
| `done`              | 返答の終わり                               | 会話の状態、読み取れた条件、こだわり                                                                                                                                                       |

### スタッフと作業

| スタッフ（`staff`）        | 作業（`task`）              | 使うツール                                                                                                            |
| -------------------------- | --------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `concierge` コンシェルジュ | —                           | `note_conditions`（画面にイベントは出さない）、`update_itinerary`、`verify_festival`                                  |
| `researcher` 祭り調査係    | `find_festivals` 祭りを探す | `search_festivals`                                                                                                    |
| `scout` 周辺係             | `find_nearby` 寄り道を探す  | `search_nearby`                                                                                                       |
| `planner` 旅程係           | `plan_route` 道のりを調べる | `get_access`、`research_route`、`research_trip`、`get_weather`、`search_nearby`、`search_lodging`、`update_itinerary` |

### 吹き出しの文章

吹き出し（`bubble`）の文章は、サーバーがツールの入力と結果から決まった型で作ります（`apps/server/src/agent/bubbles.ts`）。モデルには書かせないので、速く、毎回同じ見た目になります。英語の画面では、画面がイベントの型から辞書で言い直します（[画面の言語](#画面の言語)）。

- 吹き出しは短くし、店内のようすの窓には、くわしい文（`detail`）を出す。くわしい文は、調べた中身と見つけたもの（件数と種類、代表の1件の名前と会場からの距離、乗り換えの回数と所要時間など）を言う
- 店・宿・祭りの名前や天気の空模様などの集めた文字列は、信用しない入力として扱う。空白とかぎかっこを詰め、20文字で切った文字列としてだけ埋め込み、画面は文字列として表示する
- 行き方の調べの要約（`summary`）のような、モデルが書いた文は入れない。分からない値は言わない（推測で埋めない）

| 契機                             | 吹き出しの例                                            |
| -------------------------------- | ------------------------------------------------------- |
| サブエージェントの開始           | 「調べてきますね」                                      |
| `search_festivals` の前          | 「8月16日に、みなと中央駅から行ける祭りを探しています」 |
| `search_nearby` の前             | 「会場の近くで、寄れる場所を探しています」              |
| `get_access`・`get_weather` の前 | 「電車の所要時間と天気を確かめています」                |
| `research_route` の前            | 「みなと中央駅からの乗り換えを調べています」            |
| `search_lodging` の前            | 「8月15日から2泊の宿を探しています」                    |
| `search_festivals` の後          | 「2件見つかりました。いちばん上は「鈴鳴灯籠まつり」」   |
| `search_nearby` の後             | 「4か所見つけました。うち食事どころ3軒」                |
| `research_route` の後            | 「乗り換えは1回、1時間40分〜2時間です」                 |
| `search_lodging` の後            | 「宿を2軒見つけました」                                 |
| `verify_festival` の後           | 「開催予定を公式情報で確認しました」                    |

くわしい文（`detail`）の例です。

| 契機                    | くわしい文の例                                                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `search_festivals` の後 | 「希望の日に開かれる祭りを1件、前後の日を1件見つけました。いちばん上は「鈴鳴灯籠まつり」（8月16日・滋賀県鈴鳴町）です」          |
| `search_nearby` の後    | 「会場から歩いて10分以内に、食事どころを3軒、見どころを1か所見つけました。いちばん近いのは「（店の名前）」（歩いて3〜5分）です」 |
| `get_access` の後       | 「みなと中央駅から会場まで1時間50分〜2時間10分の目安です。最寄りの鈴鳴駅から歩いて10〜15分です」                                 |
| `research_route` の後   | 「みなと中央駅から鈴鳴駅まで、乗り換え1回で1時間40分〜2時間です。鈴鳴駅から会場まで歩いて約10分です」                            |
| `search_lodging` の後   | 「8月15日に泊まれる宿を2軒見つけました。会場にいちばん近いのは「（宿の名前）」（歩いて8〜12分・0.6km）です」                     |
| `get_weather` の後      | 「8月16日は晴れ時々くもり・降水確率20%・最高31℃」                                                                                |

### 調べ直しの頼みと受け（`staff.redo`）

旅程に足りないものがあるとき、スタッフどうしで調べ直しを頼み、頼まれた人が受けます。文は足りないもの（`subject`）だけから決まった型で作ります（`redoEvent`）。

| 足りないもの（`subject`） | 頼む（`request`）の吹き出し                            | 受ける（`accept`）の吹き出し                 |
| ------------------------- | ------------------------------------------------------ | -------------------------------------------- |
| `lunch`                   | 「昼ごはんの店がまだです。もう一度探してもらえますか」 | 「昼ごはんの店ですね。もう一度探してきます」 |
| `dinner`                  | 「夕ごはんの店がまだです。…」                          | 「夕ごはんの店ですね。…」                    |
| `sightseeing`             | 「寄り道の場所がまだです。…」                          | 「寄り道の場所ですね。…」                    |
| `route`                   | 「乗り換えの行き方がまだです。…」                      | 「乗り換えの行き方ですね。…」                |
| `last_mile`               | 「駅から会場までの行き方がまだです。…」                | 「駅から会場までの行き方ですね。…」          |
| `lodging`                 | 「泊まる宿がまだです。…」                              | 「泊まる宿ですね。…」                        |

頼みは、`update_itinerary` の評価が基準に届かず、作り直す回数が残っているときに出す（食事と寄り道は旅程係 → 周辺係、行き方と宿はコンシェルジュ → 旅程係）。受けは、旅程係がその頼みで `research_trip` を呼んだときに出す（[旅程の評価](itinerary.md#旅程の評価)）。

画面は、言う人の吹き出しを出し、頼みと受け渡しの記録に「旅程係 → 周辺係：「昼ごはんの店」の調べ直しを頼む」の形で残します。

### 候補カード（`tool.end` の `candidates`）

| 項目                      | 中身                                                                                                                                                                                                                         |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `festivalId`・`name`      | 祭りの ID と名前                                                                                                                                                                                                             |
| `date`・`start`・`end`    | 開催日と時刻                                                                                                                                                                                                                 |
| `venueName`・`place`      | 会場と開催地                                                                                                                                                                                                                 |
| `daysFromWish`            | 希望日からのずれ（日）。0 は希望日、負は前、正は後                                                                                                                                                                           |
| `confidence`・`confirmed` | 確度と、開催が確認できているか。`check` が要事前確認（`needs_check`）なら「要事前確認」と出して選べるようにし、それ以外で確認できていなければ「未確認」と出す                                                                |
| `highlight`               | 見どころ1つ                                                                                                                                                                                                                  |
| `source`                  | 出典                                                                                                                                                                                                                         |
| `check`                   | 候補を出す前の開催の確かめの結果と時刻（確かめていなければない）                                                                                                                                                             |
| `travel`                  | 出発の駅からの片道の所要時間を条件に照らした値：幅（`minutes`）・根拠（`basis`：data / estimate）・照らした上限（`limitMinutes`）・比べた結果（`fit`：within / uncertain / over / unknown）。泊まりの旅では上限と結果が null |

### 条件の検査と次の手（`tool.end` の `search`）

`search_festivals` の `tool.end` にだけ付きます（`SearchOutcomeSchema`）。

| 項目          | 中身                                                                                                                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`      | `found` 条件に合う祭りがある / `none` 見つからなかった                                                                                                                                                                 |
| `excluded`    | 条件から外した祭りの数（`date`・`travel`・`area`。いちばんはじめに外れた条件で数える）                                                                                                                                 |
| `nearMisses`  | 条件を1つだけ外せば出る祭り（最大3件）。候補カードと同じ形（`candidate`）と、外れている点（`miss`：`condition` と決まった型の `detail`）                                                                               |
| `suggestions` | 次の手（最大6つ）：`kind`・ボタンの文（`label`）・変える条件（`retry`）・送る発言（`message`）・変えた条件で見つかった数（`found`）。「条件を選び直す」（`edit_conditions`）だけは `retry`・`message`・`found` が null |
| `attempts`    | 探した回数（はじめの検索と、条件を変えて数え直した回数。最大6）                                                                                                                                                        |

| ------------ | ------------ |

### エラー（`error` の `code`）

| 値                     | 意味                                       |
| ---------------------- | ------------------------------------------ |
| `bad_request`          | 発言やこだわりの形が正しくない             |
| `unauthorized`         | 合言葉が違う                               |
| `rate_limited`         | 相談の回数の上限に達した                   |
| `timeout`              | 時間の上限を超えた                         |
| `tool_failed`          | ツールが失敗した                           |
| `upstream_unavailable` | 外のサービス（Claude、天気など）に届かない |
| `internal`             | そのほかのサーバーの誤り                   |

画面には `message` の一文だけを出し、詳しいことはサーバーのログに残します。

## 時間の上限

| 対象             | 上限                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | 超えたとき                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| ツール1回        | 10秒（`note_conditions` は5秒、`update_itinerary` は評価係の採点を含めて75秒、`research_trip` は経路と寄り道の調べを並べて100秒、`search_lodging` は空きがないときの宿の調べ（観点ごとに並べて動かす）を含めて95秒、`research_route` は調べ直しを含めて95秒、`search_nearby` は寄り道の調べを含めて95秒（調べは1回目を55秒、合う店がなく広げて調べ直す2回目を含めて85秒で打ち切る。調べが進んでいる間は、相談の進みとして数える）、`verify_festival` は70秒、`search_festivals` は候補を出す前の確かめを含めて70秒。確かめは1件50秒で、6件を並べて動かす） | エラーとして返し、エージェントは代わりの案を出す                     |
| 相談1回          | 進みのない時間が90秒（ツールの中の調べの進みも数える）。全体は10分（Cloud Run のタイムアウトはこれより長い660秒）                                                                                                                                                                                                                                                                                                                                                                                                                                          | 途中までの結果を出し、「もう一度」を案内する                         |
| 宿の空きの取得   | 8秒（呼び出しは1本ずつ、1.5秒以上の間隔を空ける）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | 「宿の空きを調べられませんでした」と返し、泊まる地域だけで旅程を作る |
| 天気の取得       | 5秒                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | 「予報を取得できませんでした」と出し、旅程は作る                     |
| サブエージェント | 1回の相談で最大3人、各1回                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | それ以上は呼ばない                                                   |
