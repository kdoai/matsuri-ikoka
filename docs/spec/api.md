# API と SSE イベントの仕様

## API

| メソッド | パス                  | 本文                                 | 返すもの                                                                                                                              |
| -------- | --------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| POST     | `/api/session`        | `SessionRequestSchema`（省略できる） | 201 `SessionResponseSchema`（`{ "sessionId": "…" }`）                                                                                 |
| POST     | `/api/chat`           | `ChatRequestSchema`                  | 返答を SSE のイベントで返す                                                                                                           |
| PATCH    | `/api/preferences`    | `PreferencesRequestSchema`           | SSE。旅程があり live のときは旅程係だけを動かして組み直す。それ以外（旅程がない、mock）はこだわりを変えて `done` だけを返す           |
| GET      | `/api/festivals`      | —                                    | 祭りのデータの一覧（`FestivalsResponseSchema`、`{ "festivals": [...] }`）。候補が出る前の豆知識に使う                                 |
| GET      | `/api/festivals/:id`  | —                                    | 祭りのデータ（`FestivalSchema`）。しおりの作法・地元の味・アクセス、待ち時間の小話に使う                                              |
| GET      | `/api/itinerary/:id`  | —                                    | 旅程（`ItinerarySchema`）。`:id` は旅程の ID（ログインして残していなければ、最後の保存から30日）か共有の ID（`sh-…`、作ってから30日） |
| GET      | `/shiori/:id`         | —                                    | 旅のしおり（画面で見る HTML）。公式の情報で開催予定を確かめた旅程だけ（[しおり](shiori.md)）                                          |
| GET      | `/shiori/:id.pdf`     | —                                    | 同じしおりの A4 の PDF。混み合っていたら 503（`upstream_unavailable`）と `Retry-After`                                                |
| GET      | `/shiori/assets/*`    | —                                    | しおりのフォントとスタッフの静止画                                                                                                    |
| GET      | `/healthz`・`/health` | —                                    | 死活監視。`{ "status": "ok" }`。Cloud Run の既定の URL では `/healthz` が外に出ないので、外からは `/health` を使う                    |

ログインと自分の旅の API（`/api/auth/config`・`/api/trips`・`/api/me/trips`）は [ログインと保存の仕様](account.md#api) にあります。

- 型はどれも `packages/schema`（`api.ts`）にある
- 合言葉（`ACCESS_PASSCODE`）を設定しているときは、`/api/*` にヘッダー `x-access-passcode` が要る。しおりと死活監視には要らない
- 掲載停止の祭りは、`/api/festivals` の一覧に含めず、`/api/festivals/:id` でも 404 にする
- 本番では、同じオリジンから画面（`apps/web` のビルド）も配る

### 断るときの応答

SSE を始める前に断るときと、JSON を返す API が失敗したときは、HTTP の状態コードと `ApiErrorSchema` の本文（`error` イベントの data と同じ `{ code, message, retryable }`）で返します。

| 状態 | `code`                 | いつ                                                                                |
| ---- | ---------------------- | ----------------------------------------------------------------------------------- |
| 400  | `bad_request`          | 本文の形が正しくない                                                                |
| 401  | `unauthorized`         | 合言葉が違う。ログインが要る API で、ID トークンがない・確かめられない              |
| 403  | `unauthorized`         | ほかの利用者が残した旅を残そうとした                                                |
| 404  | `bad_request`          | 相談・旅程・祭りが見つからない。ログインを用意していないのに旅の API を呼んだ       |
| 409  | `bad_request`          | 同じ相談の前の返事を作っている途中（retryable）。旅程がまだないのに旅を残そうとした |
| 413  | `bad_request`          | 本文が大きすぎる                                                                    |
| 429  | `rate_limited`         | 1日の相談の回数の上限（全体、または IP ごと）                                       |
| 503  | `upstream_unavailable` | 同時に返事を作れる数を超えた（retryable）                                           |

### POST /api/chat

本文は `ChatRequestSchema` です。

```json
{
  "sessionId": "…",
  "message": "8月16日に行ける祭りはありますか",
  "preferences": {
    "party": "adults",
    "spot": "auto",
    "food": "stalls",
    "move": "train"
  }
}
```

- `message` は前後の空白を除いて1〜1000字
- `preferences` は画面で選んでいるこだわり（[旅程の仕様](itinerary.md#こだわりの効果)）

## SSE イベント

1つの発言に、SSE の接続を1本使って返します。

- 各イベントは `event:` に種類、`data:` に JSON を入れる。形は `SseEventSchema`
- 最後に必ず `done` を送って閉じる。相談の状態が `done` の形に合わないときも落とさず、読み取れた条件を空にして送る
- 15秒ごとに空のコメント行を送り、途中で接続が切られないようにする
- 接続が切れても自動で再接続はしない。会話欄に「もう一度送る」ボタンと、返事が最後まで届かなかったことと送り直せることを伝える一文を出す（`done` を受け取らずに閉じたときも同じ）
- `done` が届かないまま閉じたら、画面は `/healthz` でサーバーが応答するかを確かめる。応答しなければ、上の一文の代わりに「サーバーにつながらない」と出す
- 画面の側でイベントの反映に失敗しても、接続が切れたことにはせず、続きを受け取る
- 閉じたら、接客サーバーはログに `turn_end` を1行残す。終わり方（`done`・`error`・`timeout`・`client_closed`：done の前に利用者の側から切れた）、`error` の `code`、`done` を送れたか（`doneSent`）、送ったイベントの数、所要時間。会話の本文は残さない
- 送る前（`encodeSseEvent`）と受け取ったあと（`decodeSseEvent`）に、どちらもスキーマで検証する

| イベント            | いつ                                       | 主な中身                                                                                                                                                                       |
| ------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `staff.start`       | スタッフ（サブエージェント）が作業を始めた | スタッフ、作業の種類、吹き出し                                                                                                                                                 |
| `tool.start`        | ツールを呼ぶ前                             | ツールの呼び出し ID、ツール名、スタッフ、吹き出し                                                                                                                              |
| `tool.end`          | ツールが終わった                           | 成否、吹き出し、件数。`search_festivals` なら候補（最大3件）、`search_nearby` なら地図に打つ場所                                                                               |
| `itinerary.updated` | 旅程が保存された                           | 旅程の全体と、前の版からの差分（追加・変更は予定の ID、削除は ID と名前）                                                                                                      |
| `festival.verified` | 開催を確かめた                             | 祭りの ID、確かめた日付、場面（`scope`：`candidate` は候補を出す前、`itinerary` は確定前。省略は `itinerary`）、結果（予定どおり・変更・中止・確認できず）、出典、確認した時刻 |
| `message.delta`     | コンシェルジュの返答の続き                 | 返答の ID と文章の続き                                                                                                                                                         |
| `error`             | 何かがうまくいかなかった                   | 種類、利用者に見せる短い一文、もう一度送れば直るか                                                                                                                             |
| `done`              | 返答の終わり                               | 会話の状態、読み取れた条件、こだわり                                                                                                                                           |

### スタッフと作業

| スタッフ（`staff`）        | 作業（`task`）              | 使うツール                                                                           |
| -------------------------- | --------------------------- | ------------------------------------------------------------------------------------ |
| `concierge` コンシェルジュ | —                           | `note_conditions`（画面にイベントは出さない）、`update_itinerary`、`verify_festival` |
| `researcher` 祭り調査係    | `find_festivals` 祭りを探す | `search_festivals`                                                                   |
| `scout` 周辺係             | `find_nearby` 寄り道を探す  | `search_nearby`                                                                      |
| `planner` 旅程係           | `plan_route` 道のりを調べる | `get_access`、`get_weather`、`search_nearby`、`update_itinerary`                     |

### 吹き出しの文章

吹き出し（`bubble`）の文章は、サーバーがツールの入力から決まった型で作ります。モデルには書かせないので、速く、毎回同じ見た目になります。

| 契機                             | 吹き出しの例                                            |
| -------------------------------- | ------------------------------------------------------- |
| サブエージェントの開始           | 「調べてきますね」                                      |
| `search_festivals` の前          | 「8月16日に、みなと中央駅から行ける祭りを探しています」 |
| `search_nearby` の前             | 「会場の近くで、寄れる場所を探しています」              |
| `get_access`・`get_weather` の前 | 「電車の所要時間と天気を確かめています」                |
| ツールの後                       | 結果の件数（「3件見つかりました」）                     |
| `verify_festival` の後           | 「開催予定を公式情報で確認しました」                    |

### 候補カード（`tool.end` の `candidates`）

| 項目                      | 中身                                                                 |
| ------------------------- | -------------------------------------------------------------------- |
| `festivalId`・`name`      | 祭りの ID と名前                                                     |
| `date`・`start`・`end`    | 開催日と時刻                                                         |
| `venueName`・`place`      | 会場と開催地                                                         |
| `daysFromWish`            | 希望日からのずれ（日）。0 は希望日、負は前、正は後                   |
| `confidence`・`confirmed` | 確度と、開催が確認できているか。確認できていなければ「未確認」と出す |
| `highlight`               | 見どころ1つ                                                          |
| `source`                  | 出典                                                                 |
| `check`                   | 候補を出す前の開催の確かめの結果と時刻（確かめていなければない）     |

### 会話の状態（`done` の `stage`）

| 値           | 状態         |
| ------------ | ------------ |
| `hearing`    | 聞き取り     |
| `candidates` | 祭りの候補   |
| `itinerary`  | 旅程の案     |
| `revising`   | 修正         |
| `verifying`  | 確定前の確認 |
| `shiori`     | 旅のしおり   |

状態の移り方は [接客エージェントの仕様](agents.md#会話の流れ) にあります。

### エラー（`error` の `code`）

| 値                     | 意味                                       |
| ---------------------- | ------------------------------------------ |
| `bad_request`          | 発言やこだわりの形が正しくない             |
| `unauthorized`         | 合言葉が違う                               |
| `rate_limited`         | 相談の回数の上限に達した                   |
| `timeout`              | 時間の上限を超えた                         |
| `tool_failed`          | ツールが失敗した                           |
| `upstream_unavailable` | 外のサービス（Claude、天気など）に届かない |
| `internal`             | そのほかのサーバーの誤り                   |

画面には `message` の一文だけを出し、詳しいことはサーバーのログに残します。

## 時間の上限

| 対象             | 上限                                                                                                                                                                            | 超えたとき                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| ツール1回        | 10秒（`note_conditions` は5秒、`search_lodging` は20秒、`verify_festival` は30秒、`search_festivals` は候補を出す前の確かめを含めて45秒。確かめは1件30秒で、3件を並べて動かす） | エラーとして返し、エージェントは代わりの案を出す                     |
| 相談1回          | 進みのない時間が90秒。全体は6分                                                                                                                                                 | 途中までの結果を出し、「もう一度」を案内する                         |
| 宿の空きの取得   | 8秒（呼び出しは1本ずつ、1.5秒以上の間隔を空ける）                                                                                                                               | 「宿の空きを調べられませんでした」と返し、泊まる地域だけで旅程を作る |
| 天気の取得       | 5秒                                                                                                                                                                             | 「予報を取得できませんでした」と出し、旅程は作る                     |
| サブエージェント | 1回の相談で最大3人、各1回                                                                                                                                                       | それ以上は呼ばない                                                   |

## キャッシュ

| 対象               | 置き場所                   | 期限                                    |
| ------------------ | -------------------------- | --------------------------------------- |
| 祭りのデータ       | メモリ（起動時に読み込む） | 次のデプロイまで                        |
| 天気               | メモリ                     | 30分                                    |
| 宿の空き           | メモリ（同じ条件ごと）     | 5分（空きと料金は変わるので短くする）   |
| 調べた宿の空き     | セッションの中             | 会話が続く間（旅程の泊まりにも付く）    |
| 祭りの候補         | セッションの中             | 会話が続く間                            |
| 候補の開催の確かめ | メモリ（祭りと日付ごと）   | 6時間（失敗や時間切れはとっておかない） |

## サンプルの相談

モックモードで再生する記録は [`data/samples/conversations/`](../../data/samples/conversations) にあり、形は `SampleConversationSchema` です。発言ごとに、送ってからの経過時間（`atMs`）つきでイベントを並べます。
