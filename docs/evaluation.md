# 評価

3つの壁（情報・作法・計画）をどれだけ取り除けているかを、数字で示します（[課題](problem.md#壁をどう取り除くか)）。数字は、だれでも同じ手順で出し直せるものだけを載せます。

## 何を測るか

| 壁   | 指標                                         | 測り方                                                                                                                                       | 状態   |
| ---- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 情報 | 穴場（知名度 `local`）の割合                 | 祭りのデータのうち、大手の観光サイトにほとんど載っていない祭りの割合。検索の上位に出る定番との違いを示す                                     | 測った |
| 情報 | 次の開催を公式か複数の情報源で確認できた割合 | 次の開催回が、発表済み（`announced`）で、出典の確度が `official` か `corroborated` の祭りの割合（スキーマの `isOccurrenceConfirmed` と同じ） | 測った |
| 作法 | 作法の項目が分かっている割合                 | 作法の7項目のうち `"unknown"` でないものの割合。見学だけの祭りの `howToJoin`（当てはまらない）は分母から除く                                 | 測った |
| 情報 | 1件あたりの `gaps` の数                      | 調べても分からなかったことの数の平均。推測で埋めずに残した数で、少ないほどよいとは限らない                                                   | 測った |
| 情報 | 条件の組のうち、候補を出せた割合             | 相談でよくある条件の組を、接客と同じ検索に流して集計する（[下の説明](#条件の組の測り方)）                                                    | 測った |
| 計画 | 旅程の検証で落ちた割合                       | 相談で作った旅程のうち、旅程の検証（開催時間・移動・営業時間）でエラーになった割合。旅程はモデルが組むので、Claude を呼ばないと測れない      | 未測定 |

「次の開催回」は、基準の日に終わっていない開催回のうちいちばん早いものです。すべて過ぎていれば、いちばん新しい開催回を使います。掲載停止（`optOut: true`）の祭りは数えません。

## 出し直し方

```bash
pnpm evaluate:data                       # 今日（日本の日付）を基準に集計する
pnpm evaluate:data --today 2026-11-06    # 基準の日を指定する
pnpm evaluate:conditions                 # 条件の組を検索に流して集計する（--today も使える）
```

集計は [`scripts/evaluation.ts`](../scripts/evaluation.ts)、そのテストは架空の祭りで [`scripts/evaluation.test.ts`](../scripts/evaluation.test.ts) に書いてあります。条件の組の集計は [`scripts/condition-evaluation.ts`](../scripts/condition-evaluation.ts) です。

### 条件の組の測り方

次の組み合わせ（10駅 × 2通り × 12か月 × 2通り = 480通り）を、接客と同じ検索（`runSearch`・`suggestNextSteps`）に流します。モデルも通信も使わないので、同じデータからはだれが出しても同じ数字になります。

- 出発の駅：札幌・仙台・東京・名古屋・金沢・大阪・広島・高松・福岡・那覇空港
- 泊数：日帰り・1泊
- 希望の日：基準の日の月から12か月ぶんの、「その月のどこか」と「月の最初の土曜日」
- 行き先とこだわり：おまかせ（画面の初期値）

「条件を破っていた候補」は、検索とは別のコードで、掲載停止・中止や延期の回・過ぎた日・希望の日からの外れ・日帰りの上限の超過を確かめた数です。

この数字が示すのは検索とデータの届く範囲までです。エージェントが候補をどう選ぶか、人が見て合っていると感じるか、公式の情報での直前の確かめ（画面では候補を見せる前に行います）は測っていません。

### 読み方

- 次の開催を確認できた割合が 25% にとどまるのは、来年の回がまだ発表されておらず、例年の傾向からの見込み（`expected`）の祭りが多いためです。確度が `inferred` の 96 件は、曜日や旧暦からの計算や、去年までの実績からの見込みです。候補のカードにはこの確度を出し、相談では候補を見せる前に公式の情報で確かめます
- 祭りを増やす前（基準日 2026-11-04、21 件）は 48% でした。件数を増やすときに冬や来年の祭りを多く足したので、割合は下がっています
- 作法では、服装・持ち物・写真が公式の情報に書かれていないことが多く、`"unknown"` のまま残っています。しおりでは「不明」と出し、推測では埋めません
- 候補を出せた割合は、期間で探すほうが高く、1日に絞ると下がります。1日に絞って出ないときは、探し直せば見つかる次の手を示します
- 日帰りの候補の多くは、片道の上限（初期値は2時間30分）に収まるか確かめきれないものです。上限を言われていないときは、明らかに超える祭りだけを外し、所要時間の目安を候補に添えます。上限を言われたときは、収まると分かっている祭りだけを出します
- 候補のうち開催を確かめられているものが 26% なのは、来年の見込みの回まで含めて数えているためです
