# 決まりに照らした見直し

一般的な不具合（ロジックの誤り・型・効率）は、Claude Code に組み込みの `/code-review` で見る。セキュリティは `/security-review`。このスキルでは、それらが知らないこのリポジトリの決まりを見る。

## 手順

1. 対象の差分を読む：PR なら `gh pr diff <番号>`、手元なら `git diff origin/main...HEAD`
2. 下の観点を順に当て、当てはまるものを `ファイル:行` と理由つきで一覧にする。直すかどうかの判断は、見つけたことと分けて書く
3. 見つからなかった観点も「なし」と書き、見ていない観点を残さない
4. PR にコメントするのは、ユーザーに頼まれたときだけ

## 観点

### 型と計算

- 型を `packages/schema` 以外で書いていないか。スキーマを変えたら `docs/spec/`・`data/samples/`・テストも直したか
- 日程・距離・所要時間・検証を、モデルに計算させていないか（コードで計算しているか）
- `apps/server/src/domain/` の関数が Agent SDK に依存していないか。テストがあるか

### データ

- 出典（URL・確認した日・確度）のない値が入っていないか
- 分からない値を推測で埋めていないか（`null` と `gaps`、作法は `"unknown"`）
- 店や観光地の文章・画像をコピーしていないか
- 掲載停止（`optOut: true`）の祭りが、検索や収集に出ていないか

### 安全

- 集めた文字列やモデルの文章を、HTML として埋め込んでいないか（`dangerouslySetInnerHTML`、テンプレートへのそのままの差し込み）
- 秘密の値がコード・テスト・ログ・ワークフローにないか。`.env` を読んでいないか
- エージェントのオプションが `settingSources: []`・`strictMcpConfig: true` のままか。許可する道具が増えていないか（[接客エージェントの実行の仕様](../../../docs/spec/agent-runtime.md)）
- GitHub Actions の外部のアクションが、コミットの SHA で指定されているか。`permissions` が最小か

### 開発用のものとアプリ

- スキル・エージェント・フック・`CLAUDE.md` が、リポジトリの根の `.claude/` 以外に置かれていないか
- アプリのコードが `.claude/` や `CLAUDE.md` を読んでいないか。コンテナに入っていないか（`.dockerignore`）

### テストと文

- テストが架空の祭り（`@matsuri-ikoka/schema/testing`、URL は `example.com`）で書かれているか
- コミット・PR・コメント・テスト名が、変更の中身と使う人にとっての理由だけを書いているか。実在の祭りでの相談の例がないか
- 画面：正しい状態をストアだけが持っているか。3D に出す情報が文字でも読めるか。2D の店や通りへ切り替える経路を足していないか。`prefers-reduced-motion` で 3D の動きが控えめになるか
