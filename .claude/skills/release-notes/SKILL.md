# リリースノート

## 手順

1. **範囲を決める**：前のタグ（`git describe --tags --abbrev=0`）か、ユーザーが示したコミットから `origin/main` まで。タグがなければ、範囲をユーザーに聞く
2. **集める**：`git log --format='%h %s' <前>..origin/main`。squash merge なので、1行が1つの PR にあたる（末尾の `(#12)` が PR の番号）
3. **分ける**：Conventional Commits の種類で分け、使う人に見える変更を先に書く

| 見出し           | 入れるもの                                             |
| ---------------- | ------------------------------------------------------ |
| できるようになった | `feat`                                                 |
| 直した           | `fix`                                                  |
| 祭りのデータ     | スコープが `data` のもの（足した祭りの数、直した項目） |
| そのほか         | `docs`・`refactor`・`test`・`chore`・`ci`（短く）      |

4. **書く**：
   - コミットの要約を写すのではなく、使う人にとって何が変わったかを1行で書き、PR の番号を付ける
   - 祭りの情報は、出典を確かめた事実だけを書く
   - 秘密の値や内部の URL を書かない
5. **見せる**：まず下書きをユーザーに見せる。GitHub の Release を作るのは、頼まれたときだけ

```bash
gh release create v0.2.0 --target main --title "v0.2.0" --notes-file "$TMPDIR/notes.md"
```
