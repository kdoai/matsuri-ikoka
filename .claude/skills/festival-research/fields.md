# 項目ごとの調べ方と書き方

[SKILL.md](SKILL.md) の手順3で使います。項目の並びは `FestivalSchema` と同じです。どの項目も、出典に書いてあることだけを書きます。

## 祭りそのもの

### `id`

- 祭りの名前のローマ字を、小文字の英数字とハイフンでつなぐ（例：`inagawa-hanabi`）。長音の記号は付けない
- 回数（第◯回）や年は入れない。毎年同じ `id` を使う
- 同じ名前の祭りがほかの町にあるときは、町の名前を前に付ける

### `name`

- `ja`：主催者が使う正式な名前。回数（第◯回）と年は外す
- `en`：公式の英語の名前があればそれを書く。なければ、ローマ字と種類の英語で書いてよい（例：`Inagawa Fireworks Festival`）。迷えば省略する

### `category`

主な行事で1つ選ぶ。

| 値                | 主な行事                       |
| ----------------- | ------------------------------ |
| `fireworks`       | 花火                           |
| `float`           | 山車・曳山・だんじり・屋台     |
| `mikoshi`         | 神輿・行列・時代行列           |
| `dance`           | 踊り                           |
| `fire`            | 火祭り・松明・どんど焼き       |
| `lantern`         | 灯籠・提灯・行灯               |
| `performing_arts` | 神楽・獅子舞・能などの芸能     |
| `ritual`          | 神事・法要（上のどれでもない） |
| `market`          | 市・縁日                       |
| `other`           | その他                         |

### `municipalities`・`venue`

- 開催地の都道府県と市町村。川をはさむ花火のように、主催が2つの市なら両方を書く
- 会場の名前は、主催者の案内に出てくる名前（例：「猪名川河川敷」）
- 緯度・経度は、会場の中心（花火なら主な観覧場所、行列なら出発地かお旅所）を、小数4桁（約10m）で書く。主催者の地図、住所からの公的な検索（国土地理院の住所検索など）、神社や寺・公園の公式の所在地から取る

### `scaleTier`（規模）

数で決め、来場者数の公表値は、数が分からないときの参考にだけ使う。到着の余裕（XS・S：15分、M：30分、L：60分）の初期値になるので、迷ったら小さい方にせず、数の根拠を `gaps` か報告に書く。

| 種類               | XS                              | S                      | M                                                  | L                                  |
| ------------------ | ------------------------------- | ---------------------- | -------------------------------------------------- | ---------------------------------- |
| 花火（打ち上げ数） | 1,000発未満                     | 1,000〜2,999発         | 3,000〜9,999発                                     | 10,000発以上                       |
| 山車・神輿（数）   | 1〜2                            | 3〜9                   | 10〜29                                             | 30以上                             |
| 行列（参加者）     | 50人未満                        | 50〜299人              | 300〜999人                                         | 1,000人以上                        |
| そのほか           | 1つの社寺の1つの行事、1時間ほど | 1つの会場で半日から1日 | 複数の会場をめぐる、または日ごとに違う見せ場が続く | 町じゅう、または複数日の大きな行事 |
| 来場者数（参考）   | 1,000人未満                     | 1,000〜9,999人         | 1万〜9万9,999人                                    | 10万人以上                         |

- 同じ会場で同じ行事を何日かくり返すもの（例：2日間とも同じ振る舞い）は、1日分で決める

### `popularity`・`listedIn`（知名度）

次の大手の観光サイトに、**その祭りを主題にしたページ**（題に祭りの名前があり、中心に扱っている）があるかを、Web 検索（サイト名と祭りの名前）で1つずつ確かめる。一覧の中で名前が出るだけのもの、会場の社寺や施設のページ、開いて確かめられなかったページは数えない。

| slug          | サイト                         |
| ------------- | ------------------------------ |
| `walkerplus`  | ウォーカープラス（花火・祭り） |
| `jalan`       | じゃらんnet（観光・イベント）  |
| `rurubu`      | るるぶ&more.                   |
| `tripadvisor` | トリップアドバイザー           |
| `japan-guide` | japan-guide.com                |
| `jnto`        | 日本政府観光局（Japan Travel） |

見つかった slug を `listedIn` に書き、数で知名度を決める。

| 数    | `popularity` |
| ----- | ------------ |
| 4以上 | `major`      |
| 2〜3  | `regional`   |
| 0〜1  | `local`      |

### `highlights`（見どころ）

2〜4つ。**ここでしか見られないもの・食べられないもの**を先に書く。自分の言葉で、1つ30字ほど。

### `trivia`（小話）

- 2〜4件。1件 **60字以内**、1件に1つの出典
- 由来・数・記録・言い伝えのように、出典で確かめられる事実だけ。「〜と言われる」は、出典がそう書いているときだけ
- ページの文を写さず、言い換える

## 作法（`etiquette`）

どの項目も、値か `"unknown"` を書く。出典に書いていないことを一般論で足さない。出典は `etiquette.sources` にまとめる。

| 項目            | 書き方                                                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `participation` | 一般の人は見るだけ → `watch_only`。その場でだれでも加われる（参拝や振る舞いを受けることが行事の中心のものを含む）→ `join_open`。事前の申し込み・抽選・当日の受付が要る → `join_by_application`                                  |
| `howToJoin`     | 加わり方を1文で（受付の時刻と場所、費用）。`watch_only` なら `null`                                                                                                                                                             |
| `rules`         | 主催者の「お願い」「禁止事項」から。立入禁止、場所取りのルール、ごみ、火気、ドローンなど                                                                                                                                        |
| `dress`         | 出典にある服装だけ（防寒、動きやすい服、浴衣など）                                                                                                                                                                              |
| `bring`         | 出典にある持ち物だけ（レジャーシート、懐中電灯、ごみ袋など）                                                                                                                                                                    |
| `risk`          | 危険度と、その理由を1文で（下の表）                                                                                                                                                                                             |
| `photo`         | `allowed`：撮影についての制限が見当たらず、撮影を勧める・認める記載がある。`restricted`：場所・場面・道具（三脚・ドローン・フラッシュ）に制限がある。`prohibited`：撮影しないよう求めている。何も書かれていなければ `"unknown"` |

危険度は、出典にある事実から次の決まりで付ける。

| 値       | 付けるとき                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------- |
| `high`   | 火の粉・松明・曳き回し・担ぎ・押し合いなど、主催者がけがのおそれを注意している行事に、近づくか加わる |
| `medium` | 数万人以上の混雑、入場の規制や一方通行、夜の河川敷や山道、または火を使うが観覧の場所が離れている     |
| `low`    | 見学や参拝が中心で、混雑や危険について特別な注意がない                                               |

## 開催回（`occurrences`）

- 今年（次の回）の開催回を必ず1つ書く。去年の開催回は、確かめた実績として1つ残してよい
- `status`：主催者か自治体が今回の開催を発表していれば `announced`。例年の決まりや去年の日程しかなければ `expected`。延期・中止は `postponed`・`cancelled`
  - 自治体の観光のサイト（観光協会・観光局）だけに今年の日付があり、主催者の発表が見つからないときも `announced` でよい。主催者の発表がなかったことを報告に書く
  - ページの日付が、スクリプトで毎年の「今年」に書き換わるだけの一覧（年中行事の表など）は、今年の発表に数えない
  - 今年の告知が画像のチラシにしかないときは、画像を開いて読んでよい（保存しない）
- `start`・`end`：主な行事の始まりと終わり（HH:MM）。終わりが分からなければ `null`。日をまたぐときは、終わりが始まりより前になる
- 複数日にわたり、毎日同じ時間なら `endDate` を付けて1つにする。**日によって時間や行事が違うときは、日ごとに開催回を分ける**（同じ日付の開催回は1つだけ）
- `rainPolicy`：「小雨決行、荒天中止（順延なし）」のように、出典の内容を短く。書いていなければ `null` にし、`gaps` に書く
- `note`：**当日の流れ**を短く（例：「10:00 神事、10:30 から20分ほど笑う」）。順延日など、旅程に効くことも書く

## アクセス（`access`）

- `stations`：最寄り駅と、駅から会場までの徒歩。駅名には鉄道会社を付ける（例：「阪急 池田駅」）
- `walkMinutes`・`minutes` は、出典の数字から次の決まりで幅にする。頭の中で計算しない

| 出典の書き方      | 幅                                       |
| ----------------- | ---------------------------------------- |
| 「徒歩約N分」     | `[N, N+5]`                               |
| 「N〜M分」        | `[N, M]`                                 |
| 乗換案内の結果    | `[いちばん早い経路, ふつうに乗った経路]` |
| 「約N分」（電車） | `[N, N+10]`                              |

- `fromHubs`：その地方の玄関口になるターミナル駅から最寄り駅まで、近いものを1〜2つ。関西なら、大阪（大阪駅・大阪梅田駅）、難波（大阪難波駅）、京都駅、三ノ宮（三ノ宮駅・神戸三宮駅）から選ぶ。遠くから新幹線で来る人が乗り換える駅（新大阪駅・姫路駅など）が近ければ、それを足してよい。`hub` には乗り始める駅の名前を書き（乗り換えの時間を所要時間に含めないため）、経路（`route`）に路線と乗り換えを書く（例：hub「大阪梅田駅」、route「阪急宝塚線の急行、乗り換えなし」）。乗換案内の結果を使ったら、その結果のページを出典にする
- `parking`：一般向けの駐車場がある → `available`。台数が少ない・近くの有料の駐車場だけ → `limited`。主催者が「駐車場はない」と案内している → `none`。書いていなければ `"unknown"`
- `trafficRestrictions`：交通規制を、時間と場所つきで

## 地元の味（`food`）

- `stalls`：屋台・露店が出ると出典にあれば `yes`、出ないとあれば `no`、書いていなければ `"unknown"`
- `local`：**その土地でしか食べられないもの**、その祭りの日だけのもの（振る舞い・名物の菓子・郷土料理）。どこで食べられるかを `note` に

## 周辺の場所（`nearby`）

祭りの前後に寄れる観光・食・休憩の場所を **3〜6件**。少なくとも観光1件と食1件を入れる。会場から歩けるか、最寄り駅の近くを優先する。

| 項目                   | 書き方                                                                                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                   | 場所の名前のローマ字（例：`ikeda-castle-park`）。同じ場所は、どの祭りでも同じ `id` にする                                                                                   |
| `kind`                 | `sightseeing` 観光 / `food` 食事・甘味 / `rest` 休憩（カフェ・足湯・座れる休憩所）                                                                                          |
| `summary`              | 120字以内、自分の言葉で。祝日の営業など、曜日だけで表せない休みの決まりは、ここの最後に短く書く                                                                             |
| `location`             | 緯度・経度（小数4桁）                                                                                                                                                       |
| `walkMinutesFromVenue` | 出典に会場からの徒歩の時間があれば、その幅。なければ `null`（アプリが距離から目安を出す）                                                                                   |
| `hours`                | 祭りの日の曜日と季節の営業時間。最終入場・ラストオーダーは `lastEntry`。昼と夜で分かれるなど1つの時間帯で表せないときは `null` にし、`gaps` に書く                          |
| `closedDays`           | 定休日の曜日。無休なら `[]`。定休日のほかに不定休もあるときは曜日を書き、不定休は `summary` に書く。休みが不定休だけ・分からないときは `null`                               |
| `price`                | 入場料や、料理の値段の目安（出典の数字）。分からなければ `null`                                                                                                             |
| `tags`                 | 出典で確かめられるものだけ：`indoor` 屋内 / `seating` 座れる / `kid_friendly` 子ども向けの設備や体験 / `senior_friendly` 段差が少ない・座れる / `local_food` 郷土料理・名物 |
| `popularity`           | 下の決まり                                                                                                                                                                  |
| `sources`              | 営業時間と定休日は、その場所の公式のサイトか、自治体の観光のページで確かめる                                                                                                |

- 祭りの日が年末年始・臨時休業・季節の休みにかかると分かった場所は、選ばない
- 「毎月19日」のように日付で決まる休みは `summary` に書き、祭りの日に当たる（当たるかどうか分からない）なら、選ばない
- ページの「本日の営業時間」のような、見た日だけの表示は、祭りの日の値として使わない。決まった営業時間の案内を探す
- 周辺の場所の知名度：じゃらんnet・るるぶ&more.・トリップアドバイザー・（食の場所は）食べログに、その場所のページがいくつあるか。3以上 → `major`、2 → `regional`、0〜1 → `local`

## 出典と `gaps`

- 出典の `title` には、ページの題を短く書く（例：「池田市 猪名川花火大会のお知らせ」）
- `checkedAt` は、そのページを開いて確かめた日
- `gaps` には「何が分からないか」を、行く人に効く順に書く（例：「2026年の雨天の扱い」「会場のトイレの場所」）
